# Mac 로컬 모델 실측 결과

2026-09-09 · **현재 FLUX 구성은 앱 채택 대상에서 제외한다.** Mac에서 장당 37~51초이기 때문이다. 사용자는 `JSON · 512 · seed 17`의 품질은 수용하고 디테일 축소를 요청했다. Qwen 4B는 문구·태그 품질의 우선 후보이며 모바일 성능은 미검증이다. 최종 모델 선정·앱 구현·Supabase 구축 완료가 아니다.

## 시간 안내 정정과 판단

사용자는 “리서치 때는 10초 내라고 했는데 현재 시간으로 모바일에서 못 쓴다”고 지적했다. 앞선 10초 안내에는 동일 앱·모델·기기·설정의 직접 측정 근거가 없었으며 검증된 성능처럼 안내한 것은 잘못이었다. **조사 수치·선정 목표·직접 측정값을 분리한다.**

- 현재 직접 측정: M4 / 16GB에서 JSON 384px 37.41초, 512px 38.90~50.52초. 새 프로세스 전체 경과이며 다운로드 제외다.
- 384px는 생성 4 steps 자체도 약 33초, 512px 첫 결과도 약 35초였다. 모델 로딩만 없애면 10초가 된다는 근거는 없다.
- JSON 384px MLX peak 4.49GB, 512px 4.95GB. OS 전체 peak나 앱 요구 RAM과 동일한 지표가 아니다.
- iOS/Android 직접 측정 없음. Mac 수치를 휴대폰 시간으로 환산하지 않는다.
- 기존 Stamp 45초 합격 제안은 사용자 대기 경험에 맞지 않아 폐기한다. 다음 후보는 **변환 5~10초 목표**로 성능·메모리를 먼저 확인한다. 이는 달성한 성능이 아니다. VLM 태그까지 기다리는 전체 처리 시간과 모델 준비 시간을 별도 측정한다.
- 현 FLUX 구성의 추가 스타일 튜닝·대량 실행을 중단한다. 연구용 비교 기준으로만 보존하며 모바일 제품 후보로 승격하지 않는다. 클라우드나 필터로 임의 대체하지 않는다.

## 환경과 자산

MacBook Air Apple M4, 통합 메모리 16GB, macOS 26.6. Python 3.12.10, Ollama 0.32.5, 별도 `.venv`의 mflux 0.19.1 / MLX 0.32.2. VLM과 이미지 모델은 순차 실행했다. 앱 의존성 변경·추가 학습·LoRA·클라우드 사진 추론 없음.

Pixabay는 실험 전용이다. API 검색 5회·후보 25건 중 사진 5장을 선택해 webformat JPEG 긴 변 640px로 사용했다. 검색 응답은 캐시했고 키·인증 URL은 기록하지 않았다. 사진의 출처·hash와 에이전트 사전 관찰은 Git 제외 `data/`에 있다. 정식 frozen 40장·holdout 10장은 미완료다.

사용자가 이후 카페 원본과 ChatGPT 생성 목표를 **각각** 제공했다. 로컬 `data/reference-cafe/`에 원본 1654×2044, 정규화 입력 518×640, 목표 948×1112, 수신 프롬프트·hash·관찰을 보존했다. 프롬프트는 수신 그대로 `spatial relation`에서 끝나며 완전성은 미확인이다. 추가 사용자 검수를 대기하지 않는다.

목표 도장 비교 영역은 [160,115,792,701]로 잡아 바깥 종이·인쇄된 메타데이터를 제외했다. 목표 이미지를 보고 고정한 영역이며 최초 모든 실험 이전에 확정했다고 주장하지 않는다. 목표는 하체와 주변 세부를 줄이므로 전체 픽셀 복제가 기준은 아니다. 두 사람의 자세·배치, 중앙 조명, 우상단 선풍기, 좌측 냉장고·식물, 뒤쪽 주황/초록 커튼과 주요 색 관계를 비교한다. 목표의 지명·번호·연도·태그는 사용자 제공 메타데이터이며 VLM에 정답으로 주입하지 않았다.

## 컬러 도장: JSON과 반복 검증

**사용자 확정 기준:** `json-balanced-v1/03-balanced-17.png` 수준이면 수용 가능하며 디테일은 더 줄인다. 주요 인물·사물·배치를 남기고 작은 장식·잔무늬를 단순화하는 방향이다. 기존 ChatGPT 목표를 완전히 재현해야만 통과시키지 않는다. 이 피드백은 품질 기준이며 현재 실행 시간까지 수용한 뜻은 아니다.

[stamp-prompt.json](stamp-prompt.json)의 prompt 객체를 정규화한 **JSON 문자열을 실제 모델에 전달**했다. 4 steps, guidance 1, low-RAM, 고정 가중치로 384px 1건과 512px 4건(seed 42,42,17,89)을 생성했다. 요청문·설정·이미지 hash·로그·전체 시간을 각 실행 폴더에 기록했다.

| 조건 | 전체 시간 | 원본 특징 유사도 | 목표 특징 유사도 | 에이전트 시각 관찰 |
|---|---|---|---|---|
| 수신 원문 프롬프트 | 41.37초 | 0.639 | 0.351 | 사진을 두 번 배치하고 글자를 생성했습니다. 도장 변환 실패. |
| 컬러 요청문 v5 | 42.95초 | 0.575 | 0.685 | 두 사람과 주요 배치는 남았지만 의상 색이 녹색 계열로 바뀌고 도장 질감이 부족합니다. |
| JSON · 384 · seed 42 | 37.41초 | 0.506 | 0.717 | 검정 패턴 셔츠가 녹색으로 바뀌고 패턴이 사라졌습니다. 시간을 크게 줄이지 못했습니다. |
| JSON · 512 · seed 42 | 38.90초 | 0.631 | 0.671 | 큰 배치는 유지됩니다. 어두운 패턴 셔츠가 청회색으로 밝아졌고 매끈한 선화가 강합니다. |
| JSON · 512 · seed 42 반복 | 40.59초 | 0.631 | 0.671 | 앞선 seed 42와 RGB 픽셀이 같습니다. 같은 결과의 재현은 확인했지만 품질 통과를 뜻하지 않습니다. |

동일 seed 42의 두 결과는 **RGB 픽셀이 동일**했다. 다른 seed에서는 의상 색과 패턴이 바뀌어 품질 일관성은 부족하다. JSON과 seed는 재현 조건이며 품질 보증이 아니다. 384px는 해상도를 낮춰도 속도 개선이 작고 주요 셔츠 색 보존이 더 나빴다. 사용자는 이후 seed 17을 최소 품질로 수용했다. 기존 에이전트의 색·질감 관찰은 남기되 품질 불합격 판정을 사용자 기준으로 보정한다. 이 구성도 44.95초이므로 시간/품질을 함께 충족하지는 못했다.

수치는 [DINOv2-small](https://huggingface.co/facebook/dinov2-small)의 정규화 CLS cosine이다. 원본–목표 기준값은 0.504이며 자기 비교는 1.000이다. revision `ed25f3a31f01632728cabb09d1542f84ab7b0056`, CPU·로컬 가중치·safetensors로 실행했다. 평가용 보조 모델이며 앱의 세 번째 모델 역할이 아니다. 코드·전처리는 [evaluate_similarity.py](evaluate_similarity.py), 원시 수치는 로컬 `similarity-v1.json`에 있다.

HSV 색 분포 cosine과 LBP 질감 histogram도 보조 기록했다. 전체 구도와 목표의 단순화가 달라 수치 하나로 합격·확률·품질 퍼센트를 만들지 않는다. 빠른 결과는 목표 특징 수치가 높아도 셔츠를 녹색으로 바꿨다. 최종 관찰은 메인 에이전트의 시각 평가이며 사람의 정답·사용자의 개별 승인으로 표시하지 않는다.

## VLM: 태그 자동 제공, 문구는 요청할 때만

사용자는 현재 초기 비교 화면의 문구·태그가 적절하다고 확인했다. Qwen 4B를 품질 우선 후보로 유지하며 취향 질문을 반복하지 않는다. 이 피드백을 모든 사진·모바일 실행의 통과로 확대하지 않는다.

[run_vlm.py](run_vlm.py) v4는 기본 `analysis`에서 태그·무드를 분석하고 `ai_field_note=""`를 schema와 사후 검사로 강제한다. 태그는 스탬프와 함께 제공하는 계약이다. `caption`은 명시 요청에 해당하는 실험에서만 호출하고 문구 필드 하나만 반환한다. 사용자 메모와 기존 태그를 바꾸지 않는다. 앱 연결은 아직 구현하지 않았다.

| 작업 | 한국어 | 영어 | 구조 확인 |
|---|---|---|---|
| 자동 분석 | 11.85초 | 2.88초 | 두 결과 모두 문구 빈 문자열 |
| 요청 문구 | 8.62초 | 1.33초 | 두 결과 모두 ai_field_note만 반환 |

각 작업은 ko 다음 en 순서다. 로드·프롬프트/이미지 캐시 영향을 포함하므로 언어별 고유 성능 차이로 해석하지 않는다. 초기 한국어 태그 분석만도 11.85초여서 이미지 변환과 합친 전체 모바일 대기 목표는 별도 검증이 필요하다.

카페 한국어 태그는 `카페 · 바리스타 · 커피 · 장식`, 분위기는 `따뜻한 빛 · 집중된 분위기`였다. 문구는 “따뜻한 조명 아래 작은 커피숍의 흐르는 시간”이다. `바리스타`·`staff members`는 직업/역할 추정으로 남아 있어 근거 정확성 보완 항목이다. 짧은 문구 목표는 ko 8~20자(최대24), en 4~8단어(최대60)이며 데이터 계약300자는 유지한다.

## 이전 탐색과 누적 실행

- VLM v1/v2: 3모델 × 사진5장 × 한/영, 총60건. SmolVLM은 요청문 복사, Qwen2B는 환각·언어 혼합으로 현재 구성 탈락. Qwen4B v2 10건 JSON 통과, 평균8.31초로 우선 후보였다.
- 짧은 문구 v3: Pixabay10건 JSON 통과, 평균7.42초. ko13~22자 / en29~46자. 설명조·어색한 연결은 일부 남았다. 카페 기준 사진으로 v3 추가2건, v4 분리4건. **누적 VLM76건**이며 과거 동시 문구 생성은 능력 비교이지 현재 제품 자동 생성 정책이 아니다.
- Stamp 흑백v1/v2 각각5건: 평균36.04초 /47.46초. 인물 배경·숲 지형 변형으로 실패. 사용자의 잉크 질감 선호를 흑백 색상 승인으로 해석했던 점을 정정했다.
- 컬러v3 2건: 색은 생겼지만 수채화와 지형 변경. 컬러v4 5건: 단색/세피아 편향으로 목표 미달. 카페 기준 원문/v5 2건, JSON5건 포함 **누적 Stamp24건**이다.
- 기존 형식·코드 검증 성공을 이미지 품질·정식 세트·모바일 통과로 집계하지 않는다. 모바일·대표색 알고리즘 검증은 NOT_RUN이다.

## 결과 확인과 검증

HTML 파일 편집 탭이 아닌 **브라우저 미리보기**로 제공한다. localhost 데이터 전용 서버에서 `http://127.0.0.1:8765/reference-cafe/review.html`은 원본·목표·로컬 결과7건과 태그/요청 문구·시간·판정을 표시한다. 초기 Pixabay 화면은 `/review.html`에 별도로 남겼다. 자산은 Git에 포함되지 않는다.

실행기·유사도 보조 검사13개 통과. DINO 자기 비교1.000, 동일 seed RGB 일치, v4 자동 분석의 빈 문구2건과 요청 문구 전용 응답2건을 실제 결과로 확인했다. 새 비교 화면은 브라우저에서 결과7건의 이미지/시간 전환과 문구 펼치기/접기, 초기 숨김을 확인했다. 공유 대상 텍스트29파일의 키 유출 없음과 env·사진·런타임 Git 제외, `git diff --check`를 확인했다. 기기별 모바일 성능·접근성 인수 검사를 실행한 것은 아니다.

다음 후보는 성능 근거부터 확인한다. 빠른 실행의 기기·해상도·준비시간 포함 여부가 명확하지 않으면 10초 성능을 주장하지 않는다. 제품 후보 선정과 Supabase 설정은 아직 시작 조건을 충족하지 않았다.

사전 로딩 UX: 앱 첫 화면 이후 설치 모델을 준비하고 Book 이용을 유지한다. 같은 프로세스에서 재사용하되 두 모델 동시 상주를 가정하지 않으며 메모리 압박 시 재준비한다. 이번 측정은 새 CLI 프로세스 방식이므로 앱 사전 로딩 성능 검증이 아니다.

목표 해석: 사용자는 ChatGPT 결과가 주요 요소를 모아 다시 그린 것처럼 보인다고 설명했다. 실제 생성 내부 과정은 미확인이지만 시각상 선택적 재구성과 일치한다. 다음 비교는 주변 세부/위치 일치보다 핵심 인물·사물 특징·관계·컬러 도장 표현을 기준으로 한다. 대체 모델은 [추가 조사](ALTERNATIVES.md)에서 별도로 선별한다.

## 대체 모델 SD-Turbo 추가 실측

사용자 요청에 따라 SD-Turbo의 공식 사진 입력 경로를 로컬에서 비교했다. [공식 모델 카드](https://huggingface.co/stabilityai/sd-turbo)는 img2img와 적은 단계 생성을 제공한다. 공개 FP16 snapshot `b261bac6fd2cf515557d5d0707481eafa0485ec2`의 필요한 가중치 약2.58GB만 내려받았다. Diffusers0.40.0·Accelerate1.14.0을 실험 환경에만 추가하고 기존 PyTorch2.14.0·Transformers5.16.1을 재사용했다. 현재는 로컬 평가이며 상업 등록·배포 조건은 [추가 조사](ALTERNATIVES.md)에 따로 남긴다.

| 조건 | 모델 로드 | 첫 추론 | 같은 인스턴스의 후속 추론 | 결과 |
|---|---|---|---|---|
| 강도0.5 / 실제1단계 | 2.77초 | 3.80초 | 동일설정1.05초 | 주요 인물 소실·카페 구조 변경 |
| 강도0.5 / 실제2단계 | 위 로드 재사용 | 해당 없음 | 1.26초 | 주요 인물 소실·사진과 다른 장면 |

**현재 SD-Turbo 구성 QUALITY_FAIL.** 재구성과 주변 생략은 허용하지만 사진의 핵심 인물·사물을 잃는 것은 허용하지 않는다. 약1초라는 Mac 반복 추론만으로 모바일 합격이나 앱 채택을 선언하지 않는다. 첫 로드·GPU 컴파일/캐시·이미지 인코딩·디코딩 영향을 구분하며 FLUX의 새 CLI 전체 시간과 같은 측정 구간인 것처럼 배수 비교하지 않는다. 측정은 MPS synchronize로 GPU 완료를 기다렸고 PNG 저장·다운로드는 추론 시간에서 제외했다. 모델 로드는 Python import 뒤 from_pretrained부터 MPS 이동 완료까지다.

입력416×512, seed17, 실제 JSON 요청문33토큰(77토큰 상한 안, 잘림 없음), guidance0을 고정했다. 동일 설정 반복 PNG hash는 각각 일치했다. 종료 시 MPS 할당 약2.60GB / driver약4.57GB이며 peak RSS는 미측정이다. 고정 입력의 공식 model_index에 safety checker가 없는 구성으로 실행했다. 공개 서비스나 배포를 검증한 것이 아니다.

[실행기](run_turbo.py)의 최소 입력 검사를 포함해 총14개 검사 통과. 출력6건의 파일/입력 hash·설정·로드/추론 시간은 로컬 `sd-turbo-v1/`, `sd-turbo-low-v1/`에 기록했다. 원본과 사용자 수용 FLUX seed17 기준의 DINO/HSV/LBP 보조 비교는 `sd-turbo-similarity-v1.json`, 에이전트 시각 판정은 `sd-turbo-assessment-v1.json`이다. 기준이 기존 ChatGPT ROI에서 수용된 FLUX 전체 이미지로 바뀌었으므로 이전 유사도와 직접 순위를 합산하지 않는다.

누적 Stamp는 **30건(기존24 + SD-Turbo6)**, VLM은76건이다. 브라우저 `http://127.0.0.1:8765/reference-cafe/sd-turbo-review.html`에서 기존 기준과 대체 모델을 비교한다. 현재까지 속도와 수용 품질을 함께 통과한 최종 후보는 없다.


## 2026-09-09 후속 네이티브 실행 검증

- Qwen3-VL 4B: iOS Simulator 네이티브 CLI에서 카페 사진 포함 한·영 JSON 분석을 실행했다. 앱의 Expo 연결 검증은 아니다. 한글 문구의 근거 없는 표현과 mmproj 출처 검증이 남아 최종 채택하지 않았다.
- Gemma: 네이티브 텍스트 실행과 G1–G4를 통과했지만 사진 입력 G5에서 `<unused57>` 반복 출력으로 실패했다. 종료 코드 0을 유효 분석 성공으로 보지 않는다. 후속 gate는 NOT_RUN이다.
- DreamLite: Hugging Face `diffusers` 원본과 공식 배포 코드를 대조했다. Qwen3-VL BF16 원본 3.963GiB, UNet BF16 0.727GiB, Tiny VAE BF16 4.7MiB다. 공식 MLX 기본 변환은 언어부만 Q4이고 비전부가 FP32라 2.52GiB였으며 iPhone 14 Pro Max에서 signal 9가 났다.
- DreamLite 실기기: 비전부를 BF16으로 명시한 1.660GiB artifact로 실제 사진→Qwen 조건 생성→Core ML UNet 4단계→VAE decode→1024 PNG 저장을 22.88초, peak RSS 약 1.90GiB로 완주했다. FP16 vision은 Swift BF16 attention mask와 충돌해 제외한다.
- DreamLite 공식 입력: `[Edit]: A diptych ...` 접두문과 길이 200으로 재실행했다. warm 전체는 `.all` 20.32초·약 1.59GiB, CPU 전용 14.79초·약 1.57GiB였다. 원본의 두 사람과 카페 배치는 대체로 유지했지만 평면화된 그림에 가깝고 고무도장 질감과 속도 기준에 미달한다.
- DreamLite 정본 증거: 로컬 parity 자료와 [상세 가중치·실기기 조사](DREAMLITE_IOS_ALTERNATIVES.md)에 보존했다. NAS 다운로드 구조는 품질·속도 채택 뒤로 유지한다.
- DreamLite Qwen 태그 재사용: 병렬 대신 같은 1.660GiB Qwen artifact로 `태그 → Stamp 조건 → unload → UNet`을 실기기에서 시험했다. 첫 실행은 `책, 책, 책`으로 품질 실패했지만 전체 20.36초, 태그 2.03초, peak RSS 2,057,371,648 bytes로 완주했다. 영어 요청과 중복 억제 재시도는 태그 생성 중 `signal 5`로 종료됐다. 추가 가중치 없는 경로라는 장점만으로 채택하지 않으며 현재 구성은 `QUALITY_FAIL + STABILITY_FAIL`이다.
- FastVLM 0.5B: Apple 공식 저장소 `592b4ad`와 공식 FP16 가중치를 사용해 iPhone 14 Pro Max에서 카페 기준 사진과 smoke 5장을 실행했다. 모델은 로컬 1.7GiB이며 cold load 3.62초, warm 추론 1.44~2.71초, TTFT 0.88~1.67초, peak RSS 1,103,429,632 bytes였다. 여섯 장 모두 핵심 장면과 사물을 설명했지만 태그 전용 출력 지시를 따르지 않았고 `employees`, `evening` 같은 추정이 섞였다. 가중치 약관이 연구만 허용하고 제품 개발을 제외하므로 성능 기준점으로만 보존한다.
- SmolVLM2 500M: Apache-2.0 원본의 공식 MLX 변환 revision `fa57db4`와 MLX Swift LM 3.31.3을 사용했다. 최초 약 1GB 모델 다운로드·로드가 포함된 카페 실행은 146.10초였다. 512 입력·32 token으로 고정한 준비 후 smoke 5장 연속 실행은 장당 4.19~4.24초, first chunk 3.60~3.62초, peak RSS 1,211,793,408 bytes로 완주했다. 커피잔·여성/드레스·골목/건물·숲·계단을 모두 설명했지만 `Italy` 같은 정확 위치 추정과 token 절단이 있어 raw 설명 직접 사용은 `QUALITY_FAIL`, 태그 추출 구성요소는 `PASS_WITH_SCOPE`다. 앱 재시작 뒤 모델 준비를 포함한 첫 사진은 6.09초였으므로 첫 화면 이후 비동기 준비가 필요하다.
- 실제 1차 제품 후보는 SmolVLM2의 영어 사진 설명을 사전에 고정한 허용 태그 ontology와 금칙어로 거른 뒤 한국어 표시명으로 변환하는 경로다. raw 설명은 저장·표시하지 않는다. smoke 결과를 본 뒤 만든 ontology를 합격 증거로 소급하지 않으며, ontology 고정 후 frozen·holdout 및 같은 프로세스의 `VLM 해제 → DreamLite` 3회 검증이 남아 있다. Qwen3-VL 4B는 이 경로가 실패할 때의 품질 우선 대안으로 유지한다.
- 완료된 검증 worker와 앱에 연결된 작업을 보관했고 추론 프로세스 종료를 확인했다. 미확정 모델을 앱에 연결했다고 표시하지 않는다.
