# Chroma Note 프로젝트 현황

갱신일: **2026-09-10 (Asia/Seoul)** · 앱·디자인 기준 커밋: **513ebaa**.
현재: **컬러 선화 기획·Pen 갱신 / 실제 Supabase·ERD 점검 완료 / 실제 테스트 기준 기기를 iPad mini 6로 변경 / 카페 1024→1536px 각각 6회 실측 완료 / 반복 중앙값 0.224→0.601초(+0.377초, 2.68배) / 스타일 2 제외·DreamLite 보류**. 기존 앱·서버 연결 미완료 상태는 유지한다.

## 1. 현재 범위와 변경

**다이어그램 제작:** `diagram-design` 2.6을 사용자 스킬로 설치했다. [ERD](record-erd.html)는 사용자·기록·삭제 관리 관계, [시스템 그림](system-diagram.html)은 완성품의 사진 처리·편집·저장 흐름과 기기·Supabase의 역할을 보여준다. 구현 현황은 그림에서 제외하고 이 문서에서 관리한다. 기존 Chroma Note 색상과 로컬 한글 글꼴을 사용한다. DBML CHECK 19개의 괄호 오류를 수정하여 기존 감사의 SQL 식과 정확히 일치함을 검증했다. DBML 변환 성공만으로 SQL 식 유효성을 검증했다고 보지 않는다. 원격 DB 변경은 없다. 최종 재구성한 HTML 2개의 설치 스킬 self-check와 SVG 정적 렌더 검사를 수행했다. 이전 ERD의 브라우저 검사는 최종 재구성본의 검증으로 간주하지 않는다.


**DBML:** [현행 스키마](chroma-note.dbml)에 앱 3개 테이블의 39개 컬럼·CHECK·키와 참조용 `auth.users.id/email`을 한글 설명으로 기록했다. 사용자 이메일은 Auth에서 관리하고 UUID로 기록과 연결하며 프로필·중복 사용자 테이블은 추가하지 않는다. DBML의 PostgreSQL 변환 검증을 통과했고 원격 DB 변경은 없다.


**문서 검증:** 변경 문서의 저장소 상대 링크 153개 존재 확인, `git diff --check` 통과. 선화 합성 자체 검사와 생성 fixture 실제 추론의 동일 입력 반복·선 픽셀 범위 보존 검사 통과. 원격 스키마 수정·앱 통합 테스트·Git 게시 없음.

**Pen 완료:** `design/chroma-note.pen` 저장 완료. 실제 스타일 1로 디자인용 생성 원본을 변환해 선화 이미지 51곳·문구 71곳을 갱신했다. 루트 60개·재사용 15개·placeholder 0개, 대표 7화면 시각 검사와 PNG 19개 내보내기 완료. clipping 19개는 비활성 텍스트 11개·스크롤/확대 영역 8개로 구별했다. 앱 UI는 변경하지 않았다.

**최신 기획 전환:** 컬러 선화 다이어리. 문구 제안은 “그날의 색을, 선으로 남기다.”이며 최종 브랜드 승인은 아니다. 제품·기술·ADR·용어집·디자인 기준을 원본 RGB 선 마스킹으로 맞춘다. 아래 실험 기록은 날짜와 처리 단계별 근거이며 초기 실패를 최신 결과로 읽지 않는다.

**Supabase 실제 점검:** `chroma-note-dev`의 migration `20260910082557` 확인. `public.stamp_records` 31열·0행과 내부 관리 2개 테이블, RLS·private PNG Storage가 존재한다. 사용자 직접 쓰기는 차단되어 있고 custom RPC·Edge Function은 0개다. 단일 기록 테이블은 유지하되 `ai_field_note_edited`, 태그·팔레트 항목 검증과 서버 저장 수명을 구현해야 한다. 이번 점검은 읽기 전용이며 [실제 ERD·차이](06_DATA_MODEL_REVIEW.md)를 작성했다.


사용자는 제공한 신규 기획 팩·Handoff·인포그래픽을 바탕으로 기존 기획 문서 갱신을 요청했다. 후속으로 **출시 범위 제외**, **실제 결제 문서는 Phase 2**, **카메라 대신 사진 임포트 중심**으로 방향을 좁혔다.

- 초기 조사 기록: **2026-09-10 신규 지시로 선화 변환 방안을 처음부터 조사했다.** [선화 연구](../experiments/model-selection/LINE_ART_RESEARCH.md)가 이번 목표·후보·미검증 항목·5장 검증 경로의 진입점이다. 로그인 예시 이미지를 직접 확인했으며 실제 사진 변환 성공 사례로 간주하지 않는다. 과거 모델·프롬프트·실험 성공/실패를 후보 선정 전제로 삼지 않았다.
- 대상 앱 기능: 임포트 → 대표색 → 로컬 VLM → 원본색 컬러 선화 → 사용자 비교 확인 → 기록 요약·영역별 편집 → Supabase 저장 → Book.
- 초기 원출력 결과(후속 컬러 마스킹 이전): **Informative Drawings 공식 두 스타일로 5장씩 변환해 원출력 10장·비교 페이지·ZIP을 만들었다.** 큰 구도가 남아도 음식 식별·숲의 식생 표현이 무너지고 목표의 정돈된 잉크 선·해칭에 못 미쳐 `QUALITY_FAIL`로 판정했다. 모바일 변환·실기기 실행·앱 통합은 하지 않았다. 로그인·Supabase·DreamLite 작업은 재개하지 않았다.
- 사용자 후속 의견으로 **스타일 2는 제외**했다. 비교 화면·다운로드는 스타일 1을 제공하며, 최초 두 스타일 실험 기록은 보존한다. 이후 컬러 마스킹에 대한 사용자 개선 평가와 최종 제품 품질 통과는 구분한다.
- 최신 디테일 요청: **같은 스타일 1의 입력 축소를 줄여 5장을 재추론했다.** 카페는 긴 변 512→1024px, 나머지는 원본 한계로 512→640px. 옷 무늬·손/컵·진열품은 더 남지만 얼굴 내부·숲의 식생 소실은 남았다. 카페 추론은 Mac에서 1.554→6.215초, 새 실행 프로세스 peak RSS는 4,412,735,488 bytes다. 모바일 값은 아니다. [전후 비교·실행 기록](../experiments/model-selection/LINE_ART_RESEARCH.md#8-스타일-1-디테일-보존-후속--2026-09-10)
- 최신 정정: 사용자는 색면·5색 축소·외곽선 강조를 거절하고 **원본 사진색을 이전 선에만 입히기**를 요청했다. 스타일 1 디테일 원출력의 선 픽셀 범위를 복원하고, 같은 위치의 원본 RGB를 마스크로 입힌 5장을 생성했다. 선 농도만 1.8배이며 색 축소·영역 채우기·선 확장·내부 선 선택적 약화는 없다. [결과·검증](../experiments/model-selection/LINE_ART_RESEARCH.md#10-원본색을-선에만-마스킹--2026-09-10)
- 현재 실험 목표는 **흰 배경·원본색 선·이전 선화의 디테일 유지**다. 이전 5색 면·굵은 경계 결과는 채택하지 않는다. 당시 앱·ADR·디자인은 변경하지 않았으며, 후속 문서·Pen 갱신은 아래 최신 상태를 따른다.
- 최신 사용자 요청: **“많이 좋아 진듯 이제 모바일 실폰에서 변환 시간 측정 해보자”**. 스타일 1·원본색 마스킹을 유지한 실험 전용 앱을 iPhone 14 Pro Max(iOS 26.6)에 설치해 40회 변환했다. 원본 직접 읽기·축소·추론·색 합성·PNG 저장의 warm 중앙값은 640×427 사진 4장 **0.056~0.075초**, 카페 829×1024 **0.209초**다. 모델 최초 준비는 **0.881초** 별도. 같은 정규화 입력에서는 기존 선화와 평균 0.104~0.160단계/255 차이, 색 합성은 픽셀 일치, 모든 반복 출력도 동일했다. [실폰 결과·조건](../experiments/model-selection/LINE_ART_RESEARCH.md#11-현재-선화의-iphone-실폰-시간-측정--2026-09-10)
- 앞선 원출력 품질 미달 기록은 이번 후속 검증의 중단 지시가 아니다. 이 iPhone 검증은 두 입력 모양·기기 1대의 짧은 반복 시험이며, 후속 iPad 측정은 별도 기록한다. 제품 앱 통합·Android·시뮬레이터·임의 크기 입력·장시간 자원 시험·최종 채택은 별개다. 원본을 iOS에서 직접 읽고 축소할 때 Mac 전처리와 일부 미세선 차이가 있어 품질 개선 후보로 남긴다.
- 최신 기기·해상도 지시: **“진행해 보고 시간이 얼마나 늘어 나는지 체크” → “실 테스트는 이제 아이패드미니6로 하자”**. 이후 실기기 기준은 iPad mini 6다. 카페 원본을 iPad mini 6(iPadOS 26.6.1)에서 1024px와 1536px 각각 최초 1회+반복 5회 변환했다. 반복 중앙값 **0.223789→0.600536초**, 증가 **0.376747초(+168.3%, 2.68배)**. OS 앱 프로세스 peak footprint는 **87.3→177.6MiB**이며 전체 시스템/모델 메모리의 총합이 아니다. 색 합성·12회 반복 픽셀 일치·시간 구간 합계를 검증했다. 같은 표시 크기의 확대 비교에서 선이 가늘고 정돈되는 차이는 있지만 얼굴·손 정보의 큰 개선은 관찰하지 않았다. [결과·한계](../experiments/model-selection/LINE_ART_RESEARCH.md#12-ipad-mini-6에서-1024px1536px-비교--2026-09-10). 해상도 변경만 시험했으며 추가 Lanczos 전처리·실수 마스크 합성은 아직 적용하지 않았다.
- 2026-09-10 저장 공간 정리: 사용자 요청으로 이전 FLUX·SD-Turbo·DreamLite·LCM/DreamShaper·Gemma3n 가중치, 변환/빌드 중복본, 이전 DINOv2 평가 모델과 스타일 2 가중치 **약 82.61GB(76.94GiB)**를 삭제했다. 실제 여유 공간은 **12.25→95.57GB**로 늘었다(실시간 시스템 사용량·APFS 영향으로 삭제 파일 합계와 다름). Qwen3-VL·SmolVLM 계열의 태그·메모용 데이터와 현재 스타일 1 원본/Core ML 모델, 실행 환경, 사진·결과·측정 기록은 보존했다. 보존 대상 81개 파일의 크기·수정 시각 불변, Ollama 3개 모델의 메타데이터 읽기, 스타일 1 가중치 로드와 실제 사진 Core ML 추론·색 합성을 확인했으며 기존 선화와 픽셀 차이는 0이었다. 태그·메모 생성 추론은 다시 실행하지 않았다. 삭제한 과거 모델의 재실행에는 가중치 재다운로드/변환이 필요하다. [로컬 정리 내역](../experiments/model-selection/data/model-cleanup-20260910/summary.json)
- 저장소에는 최신 명세·설계 결정·현황만 유지한다. 사용자 원본·다른 프로젝트의 모델·실기기 데이터는 모델 정리 대상에서 제외한다.

## 2. 실제 구현 사실

- src/app/_layout.tsx: 헤더 없는 Expo Router Stack.
- src/app/index.tsx: 모듈로 분리한 src/ui/AppDemo.tsx 진입. 인증·Book·처리·비교·요약·편집·상세 UI를 연결했다.
- 화면 전환·초안·Book·편집은 메모리 상태와 디자인 이미지 fixture로 동작한다. 실제 Supabase 인증/저장, 기기 사진 임포트, 대표색 추출, VLM·선화 모델 연결은 아직 앱에 통합하지 않았다. 앱 종료 후 영속 저장을 보장하지 않는다.
- 저장 전 요약과 상세는 공통 `RecordArtwork`로 Stamp·날짜/장소·사용자 글·AI 글·전체 태그를 함께 표시한다. 상세 Stamp는 사진 전용 팝업에서 iOS 네이티브/Android 제스처 기반 1~4배 핀치 확대·이동·초기화를 제공한다.
- 상세의 내보내기는 같은 기록을 1080px PNG로 합성해 OS 사진 보관함에 추가한다. 원본 사진·버튼·상태 문구는 출력하지 않으며, 권한·캡처·저장 실패를 구분한다.
- Expo SDK 57용 ESLint 설정과 직접 의존성을 추가했고 `npm run lint`를 검증 명령으로 사용한다. 별도 테스트 러너 대신 현재 핵심 로직의 소형 실행 검사를 유지한다.
- 패키지 관리는 npm으로 통일하고 `package-lock.json`만 유지한다.
- EAS 연결 정보가 있다는 사실을 Development Build나 출시 완료로 쓰지 않는다.

## 4. 작업 체크리스트와 완료 기준

**AI 모델 선정과 UI 구현 병행 → 선정 모델·서버 연결 → 통합 검증** 순서다. 2026-09-09 최신 사용자 요청으로 모델 선정 전 UI 구현을 승인했다. 앞선 모델 우선 기록은 실제 모델 연결의 선행 조건으로 유지하며 UI 착수를 막지 않는다. UI는 기존 Pen·명세와 명시적인 테스트 대역으로 구현한다. 실제 모델·Supabase 데이터 연결은 아직 남아 있다.

모델 선정에는 Mac 품질 비교와 iOS·Android 목표 기기의 실행 가능성 검증이 모두 포함된다. 모바일 검증용 최소 실행기는 모델 실험 범위이며 제품 프론트엔드·인증·저장 연동을 포함하지 않는다. 품질이나 목표 기기 검증이 미완료면 후보 선정은 잠정 상태로 남기고 앱 작업의 선행 조건을 충족한 것으로 보지 않는다.

- **해결한 SMTP 오류:** 2026-09-09 17:05·17:09 KST 발송은 Gmail `535 5.7.8 Username and Password not accepted`로 실패했다. Username·발신 주소가 같은 전체 Gmail 주소임을 확인했고, 사용자가 앱 비밀번호의 공백을 제거해 재입력한 후 발송 HTTP 200으로 전환됐다. 비밀번호 재발급도 논의되었으므로 과거 원인을 공백 하나로 단정하지 않는다.
- **인증 검증 완료:** 본인 Gmail로 발송한 가입 코드 6자리를 사용자가 로컬 입력 파일에 입력했다. 공개 키 `/auth/v1/verify` HTTP 200, access/refresh token 발급, 발급된 세션으로 `/auth/v1/user` HTTP 200 및 대상 이메일·인증 완료 상태를 확인했다. 플러그인 SQL에서도 대상 계정 1개·인증 완료 1개를 확인했다. 테스트 세션은 `logout?scope=local` HTTP 204로 로그아웃했고 토큰은 파일·로그에 남기지 않았다. `.env.auth-test.local`의 코드는 검증 후 비웠으며 Git 제외·권한 `600`을 유지한다. 테스트 계정은 보존한다.
- **남은 검증·다음 단계:** 신규 가입 발송→수신 코드→인증→세션 조회→로그아웃 경로는 통과했다. 기존 계정 재로그인용 메일·잘못된 코드·만료·재발송 제한·앱 세션 복원은 아직 미검증이다. 초기 기록 당시 DB·Storage는 미구현이었으나 2026-09-10 실제 점검에서 초기 적용을 확인했다. 서버 함수·앱 Supabase 클라이언트와 GitHub 자동 배포는 미완료다. 초기 환경·정상 인증 검증과 전체 SB-03 완료를 구별한다. SB-06에서 준비한 서버 env의 실제 사용 방식을 연결한다.

### 앱 내부 모델 연결 검토 — 2026-09-09

- 「로컬 AI 모델 테스트 환경 확인」 대화와 실제 `ios-smoke/run.sh`를 대조했다. 기존 Qwen 결과는 `simctl spawn`으로 실행한 별도 네이티브 실행기이며 Mac 절대 경로와 CPU 설정(`-ngl 0`, `--no-mmproj-offload`)을 사용한다. Expo 앱의 파일 접근·브리지·추론·결과 표시와 실기기 성능을 통과한 근거가 아니다.
- 현재 Expo Go는 UI 확인용이다. 앱 내부 추론에는 모델 네이티브 코드가 포함된 자체 빌드가 필요하다. `expo-dev-client`는 개발 편의를 위한 구성이고 그 라이브러리 자체가 필수 조건은 아니다. [Expo 공식 안내](https://docs.expo.dev/develop/development-builds/introduction/)
- `llama.rn`은 Expo 설정과 로컬 사진·GGUF·mmproj 입력을 지원하는 연결 후보다. 현재 SDK 57·React Native 0.86·Qwen 가중치/프로젝터 조합의 빌드와 실행 호환성은 미검증이며 채택 확정이 아니다. [공식 저장소](https://github.com/mybigday/llama.rn#multimodal-vision--audio)
- 최종 모델 선정에는 앱 저장공간의 모델/사진 → 네이티브 호출 → 태그 JSON 검증 → 화면 표시의 완주가 필요하다. 첫 로드·재사용·취소·오프라인·메모리 해제와 실기기 가속을 별도 측정한다. VLM 연결 성공은 Stamp 이미지 생성 런타임 성공을 뜻하지 않는다.
- DreamLite는 과거 이미지 생성형 후보로 실기기 단건·smoke 품질 한계를 확인했으나 현재 제품 방향과 무관해 상세 산출물과 로컬 런타임을 정리했다. 재검토가 필요하면 가중치 재다운로드와 별도 실험으로 시작한다.
