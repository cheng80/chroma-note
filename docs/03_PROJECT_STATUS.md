## 2. 실제 구현 사실

- `src/app/_layout.tsx`는 Expo Router Stack, `src/app/index.tsx`는 `src/ui/AppDemo.tsx` 진입이다.
- `useAppController`는 책임별 hook의 조합과 화면 연결만 담당한다. 인증, 기록 조회·삭제, 저장·복구, 사진 처리, 로컬 화면 동작을 분리했고 상태·영속화와 계정별 작업 권한의 정본은 각각 한곳에 둔다. 실제 3계정 저장·편집·응답 지연·재인증 복구는 E2E-05/06/08에서 통과했다. 인증·개인정보·원격 서버의 별도 검증도 현재 필수 범위에서 마감했다.
- 실제 사진은 `usePhotoWorkflow` → `src/services/photo-processing.ts` → 대표색·VLM·선화 순으로 호출한다. 요청 시 AI 메모는 `generatePhotoNote`를 별도로 호출한다. 모듈/상태 단위 검증과 실제 앱의 임포트→저장 완주는 구분하며, 예제 결과를 실제 사진의 변환 성공으로 계산하지 않는다.
- `modules/chroma-analysis`는 Qwen3-VL 4B 네이티브 연결이다. 사전 매핑 대신 JSON schema·1회 구조 보정과 한국어 8~24자/영어 4~8단어·60자 검사 코드를 반영했다. 실제 사진의 Expo 분석·문구 생성 경로는 실행했으나 최신 12건에서 schema/사실성 실패가 확인되어 품질 합격은 아니다.
- `record-lifecycle`의 begin/finalize/edit/delete/abort·정리 처리와 클라이언트 저장 호출이 구현됐다. 개발 서버는 migration 6개와 검증본 그대로의 `record-lifecycle` Edge Function이 적용됐다. Vault와 함수의 정리 인증값 불일치를 수정했고, 기존 15분 Cron과 같은 요청의 실제 HTTP 200을 확인했다. 계정 탈퇴는 사용자 지시에 따라 Settings에서 숨기고 로그아웃만 유지한다.
- 기록 날짜와 Book 필터 기간은 공통 `DateField`로 달력을 사용한다. 공통 `Sheet`는 내용이 가용 영역을 넘을 때만 스크롤하며, 짧은 시트의 바운스·스크롤 표시를 끈다.
- 공통 `RecordArtwork`로 선화·날짜/장소·전체 글·태그를 표시한다. 상세 사진 팝업은 1~4배 확대·이동·초기화를 제공한다.
- 내보내기는 같은 기록을 1080px PNG로 합성해 OS 사진 보관함에 추가한다. 권한·캡처·저장 실패를 구분하고 원본·버튼·상태 문구는 출력하지 않는다.
- 패키지는 npm/`package-lock.json`으로 관리한다. 실제 버전·검증 명령은 `package.json`을 확인한다.
- `tsconfig.json`에서 실험 `data/`를 제외해 vendor 코드 때문에 실패하던 전체 타입 검사를 해결했다. EAS 연결·Expo Go UI 검증과 네이티브 모델 포함 제품 빌드 완료는 별개다.

## 4. 작업 체크리스트와 완료 기준

### 4.1 체크 방법과 진행 순서

2026-09-11 사용자 요청에 따라 **디자인(D) → 기능 구현(I) → 검증(T) → 전체 순환(E2E)**을 나눈다. 각 번호는 유지하며 새 항목은 덧붙인다. 제품 요구의 정본은 [SR-FR-001~013](01_PRODUCT_SPEC.md#4-기능-요구사항), 화면 기준은 [Pen](../design/chroma-note.pen)과 최신 사용자 결정이다.

- `[x]`는 그 줄에 적힌 범위만 통과했다는 뜻이다. I 체크는 구현 확인이며 T의 실제 실행을 대신하지 않는다. 부분 구현·실패·미실행·배포 대기는 `[ ]`로 두고 이유를 적는다.
- **한 항목 통과 직후** 해당 체크와 근거를 갱신한다. 모든 작업이 끝날 때 한꺼번에 체크하지 않는다. 근거에는 날짜, 명령/조작, 대상 코드·기기·서버, 실제 결과를 남긴다.
- 아래 근거 `CODE`, `AUTO`, `COLOR`, `LINE`, `VLM`, `SHEET`, `AUTH3`, `ACCESS3`, `REMOTE`, `PEN`은 §6의 기록을 가리킨다. 별도 날짜가 없으면 2026-09-11이다. 이전 검증은 당시 범위만 유지한다.
- 변경이 기존 근거에 영향을 주면 해당 항목을 다시 미체크하고 회귀 검사를 한다. 영향을 받지 않은 통과 검사를 반복 확대하지 않는다.
- 대역·소스 문자열 검사, 실제 네이티브 검사, API 검사, 앱 화면 검사를 합산해 ‘앱 완료’나 임의 진행률로 바꾸지 않는다. 필수 D/I/T와 전체 순환을 모두 통과해야 기능 완료다.
- **2026-09-12 사용자 확정:** 현재 앱 검증 대상은 **기존 iPhone 17 Pro / iOS 26.5 Simulator 한 대**다. 현재 범위의 필수 D/I/T와 E2E-01~11을 모두 통과해야 **iPad mini 실기기 검증**을 시작한다. 첫 정상 순환뿐 아니라 오류 복구·계정 격리·일반 화면 회귀까지 확인한다. 추가 접근성 요구와 전수 검사는 완료 조건에서 삭제했다. 미실행·실패·시뮬레이터에서 확인하지 못한 항목을 통과로 처리하거나 임의로 실기기로 넘기지 않는다. 아래 현재 앱 체크의 `iPhone`은 이 Simulator를 뜻하며, 실기기에서 수행한 과거 측정은 별도 근거다. 계정 탈퇴·Android·출시·결제는 기존 후속 범위로 유지한다(§4.6).
- **2026-09-12 사용자 확정:** 추가 접근성 요구와 전수 검사 완료 조건을 삭제한다. 이미 반영한 기본 지원과 검증 기록은 보존한다. 현재 확인 대상은 일반 화면의 가독성·터치·키보드, 정상 모션, 핵심 기능·오류 복구·데이터 보존이다. 범위에서 삭제한 검사는 통과로 바꾸거나 다음 단계의 필수 작업으로 이월하지 않는다.

- 사진 선택은 화면 콜백/서비스/Expo/native 진입 시각, 타임스탬프가 있는 연속 캡처, iOS 로그로 측정했다. 선택/취소 후 반환하는 Promise 시간을 선택창 표시 시간으로 사용하지 않았다. 준비된 앱 반복 실행은 콜백→native **2ms**, 사진 목록이 나타난 캡처는 **0.42~0.59초**였다. 앱 재실행 후 첫 호출은 콜백→native **17ms**, 목록이 나타난 캡처 **2.61~2.77초**였다.
- 첫 호출 native 진입 이후 iOS 로그는 PhotosPicker 확장 준비 **1.284초**, 원격 화면 준비 콜백 **1.490초**, 루트 화면 초기화 시작 **1.587초**, `willAppearAnimated` **2.470초**, `didAppear` **3.008초**였다. 이번 지연은 주로 선택창 표시 전 초기 준비에서 발생했고 전환 자체는 약 **0.539초**였다. Slow Animations 상태값은 0, 해당 구간 메모리 경고는 없었다.
- 앱 시작 직후 모델이 `preparing`인 별도 실행도 측정했다. 콜백→native **5ms**, 목록이 나타난 캡처 **1.76~2.00초**였다. 동시 2초 샘플에서 main 96.4%, JS 94.0%는 이벤트 대기였고 별도 분석 큐의 모델 파일 읽기·SHA256 검증·로딩이 관찰됐다. 이 동시 실행만으로 모델 준비가 선택창 지연의 직접 원인이라고 단정하지 않는다. 시스템 선택창 내부 병목과 실기기 성능은 미확정이며, 근거 없는 대기시간 조정·피커 교체는 적용하지 않았다. 성능 비교는 [Apple의 실기기 프로파일링 권고](https://developer.apple.com/documentation/xcode/improving-your-app-s-performance/)를 따른다.
