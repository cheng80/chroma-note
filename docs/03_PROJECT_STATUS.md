## 1. 현재 범위와 변경

- 제품은 사진의 원본 RGB를 선에 입힌 흰 배경 컬러 선화 다이어리다. Informative Drawings `style1` 선 마스크에 같은 위치의 원본색을 적용한다. 스타일 2·색면 채우기·5색 양자화·외곽선 확장·거친 인쇄·확산형 이미지 생성은 현재 범위가 아니다.
- **2026-09-11 사용자 확정:** 선화는 실험 후보가 아니라 확정 기능이다. 입력과 옵션을 바꿀 수 있는 [독립 모듈](../modules/chroma-lineart/README.md)로 분리한다. VLM 선정·앱 전체 연결·기기별 품질 검증을 선화 채택 여부와 혼동하지 않는다.
- **후속 사용자 결정:** 화면 이름은 **컬러 스케치 / color sketch**로 통일한다. 내부 `stamp` 식별자는 유지한다. Book의 ‘첫 순간을 컬러 스케치로 남겨보세요’와 공통 화면·접근성 문구를 바꿨고, Pen 동기화는 별도 미완료다.
- 태그는 사진 처리 시 자동 분석하고 AI 메모는 사용자 요청 시에만 생성한다. 사용자 메모를 자동으로 덮어쓰지 않는다.
- **2026-09-11 후속 결정:** 계정 탈퇴는 후순위이며 현재 iPhone 순환의 완료 조건에서 제외한다. 나중에 이메일 OTP 재인증을 거쳐 진행한다. 활성/탈퇴 상태 관리와 재가입 시 기존 데이터 복원은 검토안이며 보관 기간·계정 연결·영구 삭제 정책은 아직 미정이다. 현재 DB·Auth 삭제 동작을 변경하지 않는다.
- 원본과 파생 원본은 기기에서만 처리하고, Supabase에는 완성 선화 PNG와 기록 정보를 계정별 비공개로 보관한다. 앱 전체에서 이 경계가 검증됐다는 뜻은 아니다.
- 최신 문서만 유지한다. 현재와 모순되는 과거 작업 지시·미착수 표기·폐기한 실험 비교 기준을 제거했다. [제품](01_PRODUCT_SPEC.md)·[기술](02_TECH_SPEC.md)·[ADR](adr/ADR-003-stamp-record-direction.md)이 계약 정본이다.
- 이전 Git 정리는 `b04f8cf`로 main에 반영됐다. 이번 시작 시 로컬/원격 main만 존재하고 추가 Worktree가 없음을 확인했다. 보존용 stash는 자동 폐기하지 않는다. 완료 조건은 [작업 흐름 §7](04_WORKFLOW.md#7-git데이터-보호)을 따른다.
- 폐기한 FLUX·SD-Turbo·DreamLite 등 Stamp 생성 실험의 코드·산출물·의존성을 정리했다. VLM·현재 선화 자료와 SmolVLM2 ontology adapter·검증은 보존했다. 삭제한 로컬 정리 보고서 링크를 현재 증거로 사용하지 않는다.

## 2. 실제 구현 사실

- `src/app/_layout.tsx`는 Expo Router Stack, `src/app/index.tsx`는 `src/ui/AppDemo.tsx` 진입이다.
- `useAppController`에 Supabase 인증·기록 저장소·시스템 사진 선택·SQLite 초안 연결 코드가 추가됐다. 기존 fixture 기반 처리 UI와 실제 연결 코드가 공존하며, 전체 저장 수명·계정 변경·오프라인 복구 검증은 완료되지 않았다. 코드 존재를 실제 서비스 통합 완료로 간주하지 않는다.
- 실제 사진은 `useAppController` → `src/services/photo-processing.ts` → 대표색·VLM·선화 순으로 호출한다. 요청 시 AI 메모는 `generatePhotoNote`를 별도로 호출한다. 모듈/상태 단위 검증과 실제 앱의 임포트→저장 완주는 구분하며, 예제 결과를 실제 사진의 변환 성공으로 계산하지 않는다.
- `modules/chroma-analysis`는 Qwen3-VL 4B 네이티브 연결이다. 사전 매핑 대신 JSON schema·1회 구조 보정과 한국어 8~24자/영어 4~8단어·60자 검사 코드를 반영했다. 실제 사진의 Expo 분석 전체 경로와 품질 합격 근거는 아직 없다.
- `record-lifecycle`의 begin/finalize/edit/delete/abort·정리 처리와 클라이언트 저장 호출이 구현됐다. 개발 서버는 migration 4개, `record-lifecycle` Edge Function v2 ACTIVE, Vault secret과 15분 Cron이 적용됐다. 계정 탈퇴는 사용자 지시에 따라 Settings에서 숨기고 로그아웃만 유지한다.
- 기록 날짜와 Book 필터 기간은 공통 `DateField`로 달력을 사용한다. 공통 `Sheet`는 내용이 가용 영역을 넘을 때만 스크롤하며, 짧은 시트의 바운스·스크롤 표시를 끈다.
- 공통 `RecordArtwork`로 선화·날짜/장소·전체 글·태그를 표시한다. 상세 사진 팝업은 1~4배 확대·이동·초기화를 제공한다.
- 내보내기는 같은 기록을 1080px PNG로 합성해 OS 사진 보관함에 추가한다. 권한·캡처·저장 실패를 구분하고 원본·버튼·상태 문구는 출력하지 않는다.
- 패키지는 npm/`package-lock.json`으로 관리한다. 실제 버전·검증 명령은 `package.json`을 확인한다.
- `tsconfig.json`에서 실험 `data/`를 제외해 vendor 코드 때문에 실패하던 전체 타입 검사를 해결했다. EAS 연결·Expo Go UI 검증과 네이티브 모델 포함 제품 빌드 완료는 별개다.

## 4. 작업 체크리스트와 완료 기준

### 4.1 체크 방법과 진행 순서

2026-09-11 사용자 요청에 따라 **디자인(D) → 기능 구현(I) → 검증(T) → 전체 순환(E2E)**을 나눈다. 각 번호는 유지하며 새 항목은 덧붙인다. 제품 요구의 정본은 [SR-FR-001~013](01_PRODUCT_SPEC.md#4-기능-요구사항), 화면 기준은 [Pen](../design/chroma-note.pen)과 최신 사용자 결정이다.

- `[x]`는 그 줄에 적힌 범위만 통과했다는 뜻이다. I 체크는 구현 확인이며 T의 실제 실행을 대신하지 않는다. 부분 구현·실패·미실행·배포 대기는 `[ ]`로 두고 이유를 적는다.
- **한 항목 통과 직후** 해당 체크와 근거를 갱신한다. 모든 작업이 끝날 때 한꺼번에 체크하지 않는다. 근거에는 날짜, 명령/조작, 대상 코드·기기·서버, 실제 결과를 남긴다.
- 아래 근거 `CODE`, `AUTO`, `COLOR`, `LINE`, `VLM`, `SHEET`, `AUTH3`, `ACCESS3`, `REMOTE`, `PEN`은 §6의 기록을 가리킨다. 별도 날짜가 없으면 2026-09-11이다. 이전 검증은 당시 범위만 유지한다.
- 변경이 기존 근거에 영향을 주면 해당 항목을 다시 미체크하고 회귀 검사를 한다. 영향을 받지 않은 통과 검사를 반복 확대하지 않는다.
- 대역·소스 문자열 검사, 실제 네이티브 검사, API 검사, 앱 화면 검사를 합산해 ‘앱 완료’나 임의 진행률로 바꾸지 않는다. 필수 D/I/T와 전체 순환을 모두 통과해야 기능 완료다.
- 현재 우선순위는 **기존 iPhone 17 Pro Simulator 한 대에서 실제 사진으로 한 차례 완주**다. 계정 탈퇴·iPad·Android·실기기 성능·출시·결제는 이 순환의 완료율에 섞지 않는다. 후속 검증은 §4.6에 남긴다.

| 순서 | 확인할 결과 | 다음 단계 조건 |
|---|---|---|
| 1. 기준·디자인 | 최신 문구·탭·달력·시트·화면 상태를 Pen/코드와 대조 | 화면별 미반영 항목 식별, 변경 화면은 iPhone에서 확인 |
