# Chroma Note 선화 기록 디자인 brief

> 2026-09-11 · 선화 기록 화면 설계. 핵심 문구 제안은 “그날의 색을, 선으로 남기다.”이며 브랜드 최종 승인 문구가 아니다. 기존 `stamp_records`, `stamp_image`, `Ink`, `SR-FR` 식별자는 호환용으로 유지한다. [새 Pen 디자인](../../design/README.md)은 저장 완료했으며 실제 앱 UI 반영·검증은 남아 있다.

2026-09-11 후속 결정: 현재 iPhone 기능 순환을 먼저 완성하고 계정 탈퇴 화면/흐름은 후순위로 둔다. 추후 이메일 OTP 재인증을 거치되 활성 상태·재가입 복원/보관 정책이 정해지기 전에는 복원 또는 영구 삭제를 약속하지 않는다. 기존 탈퇴 Pen 상태는 현재 필수 화면 검증에서 제외한다.

같은 날 사용자가 결과의 표시 이름을 **컬러 스케치 / color sketch**로 선택했다. 아래 기술 설명의 선화와 같은 기능이며, 앱·Pen의 사용자 문구에서는 스탬프·선화를 이 이름으로 바꾼다. 내부 DB/API 식별자는 바꾸지 않는다. 앱 문구는 반영했고 Pen 동기화 여부는 현황에서 별도로 관리한다.

공식 앱 5개의 조사 근거와 단계별 시각 결정은 [감성 디자인 리서치·Pen 개선 기준](design.md)에 정리한다. 이 brief는 공통 화면 동작·상태 계약을 유지한다. 기준 뷰포트는 `390x844`, `360x800`, `320x640`이며, 시각 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)을 참조한다.

## 1. 시각 방향과 정보 우선순위

사진을 가져온 뒤 실제 장면과 구도를 유지하려는 흰 배경 컬러 선화를 기록하는 경험을 중심으로 한다. 선화는 사진 원본의 RGB를 선 마스크에만 입히며 면을 채우지 않는다. 얼굴·손 등 세부가 소실될 수 있으므로 완벽한 보존을 주장하지 않는다.

2026-09-12 사용자 결정: 일부 윤곽·세부 생략은 고지와 결과 확인으로 수용한다. 앱의 결과 확인·요약·상세·선화 확대에서 이미지 바로 아래에 `AI 변환 중 일부 윤곽이나 세부 표현이 생략될 수 있어요.`를 12px/18px 보조 글씨로 표시한다. 영어는 `AI conversion may omit some outlines or details from the original photo.`다. 사진 변환 고지와 문구 편집의 AI 글·태그 오류 가능성 고지는 같은 파란 안내색 `#35658A` (`info`)를 사용한다. 실제 처리 오류의 붉은색과 구분하며 의미 단위 줄바꿈을 유지한다. 원본 보기·Book 썸네일·내보내기 미리보기/PNG에는 포함하지 않는다.

우선순위: 선화 → 기록 날짜/짧은 메모 → AI 글·태그 → 대표색. 사용자 문구는 “원본 사진을 흰 배경의 컬러 선화로 남겨요”처럼 단순하고 명확하게 쓴다. 기존 종이 여백·색 토큰·레이아웃을 유지하며 선화를 주 오브젝트로 둔다. 대표색 1~5개는 별도 메타데이터이며 선화 색 수를 제한하지 않는다.

첨부 포스터의 과거 원본→도장 출력은 현재 평가 기준이 아니다. 현재 목표는 사진의 피사체·구도·색 관계를 유지하는 스타일 1 흰 배경 컬러 선화다. 면 채우기, 5색 양자화, 외곽선 강조, 거친 고무 인쇄, 장면 재배치, 스타일 2, 확산 모델은 사용하지 않는다. 완벽한 픽셀 복제나 얼굴·손의 완전 보존은 목표가 아니다.

AI 원본/임포트/`Ink`/Supabase 제품 계약은 유지한다. 사진 원본은 서버에 업로드하지 않고 로컬 처리·비교에만 사용한다. VLM 태그는 사진 처리 시 자동 생성하고, AI 메모 초안은 사용자가 명시적으로 요청한 경우에만 제공하며 사용자 메모를 덮어쓰지 않는다.

인포그래픽은 분위기와 원본/결과 비교 방향을 참고한다. 그림 안의 촬영·GPS·지도·프로필·공유·다중 스타일 선택은 Phase 1에 넣지 않는다. 그 이미지의 카페 장면은 AI 품질 benchmark 원본이 아니다.

## 2. 내비게이션과 화면 조합

기본 진입은 인증 후 Book이다. 헤더에 설정을 두고, 하단 5탭은 만들지 않는다. Book의 누적 목록은 스크롤할 수 있지만 화면 전체를 기능 설명으로 길게 늘이지 않는다. 새 기록은 Book 위에서 전체화면 2단계로 열고, 닫을 때 로컬 초안을 보관한다.

| 단계/영역 | surface | trigger | result |
|---|---|---|---|
| 인증 | 전체화면 | 이메일·OTP 입력 | 세션 복원 후 Book 진입 |
| Book | 한 화면 요약 + 누적 목록 | 사진 가져오기·초안 재개·필터·Record 선택 | 빈 목록·0결과·부분 캐시·조회 실패를 구분 |
| 처리 | 전체화면 | 사진 선택 후 자동 진행·취소 | 색·VLM·선화 결과와 실패 단계 보존 |
| 새 기록 1/2 | 전체화면 비교 | 후보 확인 checkbox → “내용 확인” | 확인 전 다음/저장 차단, 후보 교체 후 재확인 |
| 새 기록 2/2 | 전체화면 기록 요약 | 글/태그·메모·날짜/장소·색 행 열기 | 시트 “적용”은 로컬 초안, “저장하기”는 서버 확정 |
| 상세 | 큰 선화 + 전체 글·태그 | 이미지 확대·더보기 | 내보내기·편집·삭제 진입 |

## 3. 새 기록과 Book 상세

Book은 폰 기본 2열, 좁은 폭에서 1열이며 태블릿은 최소 카드 폭 200과 가용 공간에 따라 3~4열이다. 선화 전체를 contain으로 보여 주고 날짜·짧은 메모를 묶는다. 첫 화면에 더 넣기 위해 글씨·터치 영역을 줄이거나 사진 속 인물을 자르지 않는다. 즐겨찾기는 이름 있는 48×48 이상의 조작으로 제공한다.

새 기록 1/2는 원본 사진과 컬러 스케치를 같은 비율로 확인한다. 폰에서는 탭으로 전환하고 이미지는 별도 전체화면으로 확대한다. 결과 확인 checkbox를 선택하기 전에는 “내용 확인” CTA를 진행할 수 없다. 사진 교체는 확인 상태를 해제한다. 컬러 스케치는 원본 주요 색과 색 관계를 살린 흰 배경 1종이며, 원본은 서버에 저장하지 않는다.

새 기록 2/2는 큰 선화, 날짜·장소, 통합 기록 글·모든 태그를 하나의 종이색 기록 카드로 함께 보여 준다. 긴 글은 해당 콘텐츠 영역에서 세로 스크롤하고 생략하지 않는다. 아래에는 문구 편집·날짜/장소·색의 세 행만 두며 저장 CTA는 고정한다. 문구 편집 시트에는 “기록 글” 입력칸 하나와 장면·태그를 둔다. “AI 문구 추가”는 같은 글 끝에 제안을 붙이며 기존 글을 덮어쓰지 않는다.

저장된 상세도 같은 기록 카드를 사용해 선화와 글·태그 전체를 함께 읽게 한다. 사진은 확대 팝업으로 열고 편집은 기존 시트를 사용한다. 더보기의 내보내기는 같은 카드의 PNG 미리보기 → 갤러리에 저장으로 이어진다. 버튼·워터마크·임의 기록 번호·원본 사진은 출력하지 않는다. 권한은 저장할 때만 요청하고 실제 사진 저장 뒤 성공을 표시한다.

## 4. 시트·모달과 상태 보존

- 시트는 문구 편집(글 입력칸 하나와 태그, 큰 높이·키보드), 날짜/장소(중간 높이·네이티브 달력), 필터(중간 높이), 색 읽기로 역할을 고정한다. 시트 중첩은 금지한다. 날짜 선택은 현재 시트 안의 네이티브 달력 영역으로 전환하고 완료 후 날짜/장소로 복귀한다.
- 기록 날짜와 필터 기간은 직접 타이핑 대신 날짜 버튼을 눌러 달력에서 선택한다. 달력을 열면 키보드는 닫는다. iOS는 현재 시트 안의 달력, Android는 시스템 달력을 사용한다. 필터 시작일·종료일은 개별 해제 가능하며 적용 전에는 임시값이다.
- 짧은 시트는 콘텐츠에 맞는 높이에서 스크롤·바운스를 끈다. 긴 내용·키보드 때문에 가용 영역을 넘을 때만 내부 스크롤을 켜고 하단 버튼은 고정한다.
- 필터 적용 전 변경은 로컬 임시값이다. 취소하면 기존 필터를 유지한다. 시트에 변경 내용이 있으면 바깥 탭·드래그·뒤로가기로 silent discard하지 않는다.
- 기본 닫기는 초안을 보관한 뒤 닫기다. “취소”는 이번 시트 편집만 되돌린다. 영속 저장 실패를 보존 성공처럼 표시하지 않는다.
- 삭제·교체·폐기는 중앙 확인 모달이다. Android back은 키보드 닫기 → 현재 시트 닫기 순서를 따르며, 변경 초안은 보존한다.
- 필수값이 없으면 하단 CTA를 진행시키지 않고 이유를 텍스트로 표시한다. 하단 CTA는 키보드·홈 영역에 가리지 않는다.

## 5. 처리·오류·보존되는 데이터

사진 가져오기, 모델 준비·다운로드, VLM, 선화 변환, 저장·복원·내보내기처럼 기다림이 생기는 작업은 UI를 막지 않는 비동기로 실행한다. 처리 중에는 현재 화면과 초안을 유지하고 실제 단계 문구와 절제된 반복 모션을 함께 보여 준다. 완료·오류·취소 시 실제 작업 상태에 맞춰 즉시 전환하며 가짜 진행률과 ETA를 만들지 않는다. 취소·재시도는 실제로 지원되는 작업에만 제공한다.

처리에 실패하면 오류 안내를 본문 맨 위에 표시하고 처리 중 제목·설명은 숨긴다. 사진과 단계별 결과는 보존하며 재시도·AI 생략·사진 교체·초안 복귀 버튼은 기존 고정 하단 영역에 둔다. 실패 이유를 읽기 위해 스크롤하도록 만들지 않는다.

모션 감각은 [BeUI](https://beui.dev/)의 Loader·Stateful Button·Action Swap과 [Kinetics](https://kinetics.colorion.co/)의 loading·spring 상태 전환을 참고한다. 두 사이트는 웹 구현 참고 자료이므로 컴포넌트 코드를 가져오지 않고, 현재 `react-native-reanimated`와 검증된 벡터 아이콘으로 재구성한다. Chroma Note의 조용한 종이 경험에 맞춰 작은 이동·투명도·스케일·상태 교체만 사용한다.

모델은 앱 첫 화면을 표시한 뒤 미리 준비한다. 준비 중에도 Book을 둘러볼 수 있고, 새 기록 진입부에 “선화를 준비하고 있어요”를 짧게 표시한다. 매 실행마다 전체화면 대기나 모달을 강요하지 않는다. 이미 준비됐다면 상태 문구를 없애고 바로 사진을 고를 수 있다. 준비가 끝나기 전에 사진을 고르면 초안을 보존하고 “준비가 끝나면 시작할게요”와 취소를 제공한다. 실패한 경우에만 재시도·돌아가기를 제시한다. 메모리에서 해제됐다가 다시 준비하는 경우도 같은 흐름을 사용하며 가짜 진행률·시간 약속은 표시하지 않는다. 모든 안내·취소 버튼은 safe area 안에 둔다.

| 상황 | 문구 기본안 | 행동 / 보존 |
|---|---|---|
| 빈 Book | 첫 순간을 선화로 남겨보세요 | 사진 가져오기 |
| 선택 취소 | 별도 오류 팝업 없음 | Book 또는 입력 확인으로 복귀 |
| 클라우드 사진 대기 | 사진을 가져오고 있어요 | 취소; 기존 초안 보존 |
| 모델 없음 | 사진을 읽을 AI를 준비해요 | 약 2.95GB·Wi-Fi 권장·다운로드 후 앱 진입 |
| VLM 실패 | 사진 설명을 만들지 못했어요 | 다시 시도·AI 설명 없이 계속 |
| 선화 실패 | 선화를 만들지 못했어요. 작업은 남아 있어요 | 다시 시도·초안으로 나가기 |
| 결과 확인 필요 | 변환된 컬러 스케치를 확인해 주세요 | 사진 바꾸기·초안으로 나가기 |
| 오프라인 저장 | 이 기기에 보관했어요. 연결되면 저장을 이어갈게요 | 저장 대기 표시, 중복 성공 toast 없음 |
| 서버 성공 | Book에 저장했어요 | 상세 열기 |
| 초안 재개 | 만들던 선화가 있어요 | 이어서 만들기·버리고 새로 만들기 |
| 저장된 기록의 원본 없음 | 원본은 보관하지 않아요. 새로 만들려면 사진을 다시 가져와 주세요 | 사진 가져오기 |
| 수정 충돌 | 다른 기기에서 기록이 바뀌었어요 | 최신 내용 확인·내 수정 다시 적용 |
| 삭제 중 | 기록을 삭제하고 있어요 | 정리 재시도; 완료로 오인하지 않음 |
| 로그아웃 전 미저장 | 이 기기의 미저장 작업은 로그아웃하면 지워져요 | 저장 후 나가기·폐기 후 나가기·취소 |

처리 취소가 완료된 이전 단계를 지우는 것은 아니다. 초안 저장 자체가 실패한 경우 “작업은 남아 있어요”를 사용하지 않는다. 무한 spinner·가짜 백분율·거짓 ETA를 표시하지 않는다.

빈 Book에는 기존 Ink 이미지와 “이런 모습으로 남아요” 안내를 배치하고 사진 가져오기를 안내한다. 사용자 기록이나 실제 모델 변환 결과로 표시하지 않는다.

## 6. 시각 기본값과 기본 사용성

2026-09-09 후속 요청으로 절제된 머테리얼 표면을 사용한다. Book 카드와 주요 행동에는 낮은 그림자, 바텀시트와 확인 모달에는 높은 그림자를 적용한다. 기존 종이색·잉크색·간격·contain 중앙 정렬을 유지하고, 모션은 무료 요소와 현재 네이티브 기능을 사용한다. 제품 화면에서 시연·데모·구현 상태 안내는 제거하고, 실제 연결과 검증 상태는 프로젝트 현황에 기록한다.

paper #F7F3EA, surface #FFFDFA, ink #292823를 사용한다. 여기서 `ink #292823`는 UI 텍스트 토큰이며 결과 선화 이미지의 색상 제약이 아니다. 결과 선화는 흰 배경 위 선에 원본색을 입혀야 한다. 기존 Pen의 단색 배경 텍스트 대비 검사 결과는 당시 범위의 기록으로 보존한다. 앱 본문은 시스템 한/영 글꼴을 우선하며, 영문 로고·날짜에 제한적인 serif를 쓸 수 있다. Pen 표현용 Noto Sans KR/Libre Baskerville이 앱 폰트 패키지 설치를 요구하는 것은 아니다.

본문 16/24 논리 픽셀, 보조 14/20, 작은 UI 최소 12를 기본값으로 삼는다. 원본 그림의 장식 글씨를 제품 본문 크기로 복제하지 않는다. 모든 조작은 48×48 이상으로 두고, 긴 글은 줄바꿈과 필요한 콘텐츠 영역의 스크롤로 읽을 수 있게 한다. 상태는 색+텍스트/아이콘으로 나타낸다.

사용자에게 표시하는 모든 문장과 여러 단어로 된 label은 `SemanticText`로 의미 단위 줄바꿈을 검토·적용한다. 안내·오류·버튼·시트·기록 본문과 내보내기의 글을 포함한다. Pen의 서체·크기·행간은 유지하고 실제 텍스트 영역의 폭을 사용한다. 원문과 작성자의 개행·빈 줄은 보존하며 표시할 때만 계산한다. 입력 필드·OS 대화상자·날짜·숫자·태그·한 줄 말줄임은 네이티브 형식을 유지한다. 영역의 폭이 바뀌면 다시 측정하고, 적합한 후보가 없으면 OS 기본 줄바꿈을 유지한다.

사용자 노출 문구에는 이모티콘, 이모지, 그림문자, 단어 사이 중앙점을 사용하지 않는다. 의미 구분은 쉼표, 줄바꿈, 조사로 표현하며 코드 식별자와 문서의 기술 구분자는 이 규칙에서 제외한다.

safe area는 모든 화면·시트·중앙 확인 모달에 필수다. 실제 OS runtime의 top/bottom/left/right inset을 적용하고, `390x844` fixture에서는 status bar 포함 top 62, bottom 34를 기준으로 하며 노치 가로 좌우 inset을 반영한다. iOS 홈 인디케이터, Android 제스처, Android 3버튼 내비게이션을 각각 처리한다. header와 footer를 분리하고 하단 CTA는 홈 영역 위에 둔다. 키보드가 보일 때 높이와 inset을 이중 차감하지 않으며, 실제 runtime 값으로 확인한다. 화면 배경과 scrim만 안전영역을 침범할 수 있고 인터랙션 콘텐츠는 침범할 수 없다.

사진/선화 설명은 사용자 확인 장면 또는 중립적 “선화 이미지”다. 미검증 AI 환각을 사실처럼 반복하지 않는다. 처리 완료·오류와 다운로드/저장 상태는 문구로 알린다.

앱은 세로 전용이다. 설계 viewport는 `390x844`, `360x800`, `320x640`, 세로 태블릿과 폴더블을 펼쳤을 때의 넓은 앱 영역이다. 펼친 영역은 회전 없이도 너비가 높이보다 클 수 있다. 기기명·방향 대신 실제 가용 너비·높이를 기준으로 Book 열 수와 글·입력·시트의 폭, 콘텐츠 스크롤을 검토한다. 접기·펼치기 전후에도 작성 내용과 진행 단계를 보존한다. 실제 동작 검증은 한/영 일반 화면, safe area·키보드, header/footer·하단 CTA와 핵심 흐름을 기준으로 하며 정적 그림·수치 검사·실기기 검증을 구별한다.

## 7. 산출물과 검증 상태

현재 산출물은 이 문서, [리서치·개선 기준](design.md)과 [Pen·PNG](../../design/README.md)다. 정적 Pen 검증 범위와 시각 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)을 참조한다. 이 brief의 실제 앱 UI, 런타임 safe area와 키보드 동작은 구현 검증으로 분리한다.

사용자의 새 디자인 요청에 따라 모델 검증과 분리해 fixture로 작성했다. 사진은 디자인용 생성 예시이고 선화는 그 사진을 실제 스타일 1로 변환한 결과다. 사용자 사진·정식 품질 benchmark는 아니다. 앱 UI, 키보드·실기기 safe area 검증은 NOT_RUN이다.

과거 도장 목표는 현재 기준에서 삭제한다. 현재 기준은 `style1` 흰 배경 컬러 선화이며, 이미지 디자인용 생성 원본은 실제 변환 출력으로 교체해 확인했다. 원본은 `generated-1788887280309.png`, 실제 선화 출력은 `design/images/lineart-style1-source-rgb.png`다. 이 원본은 사용자 사진이 아니다.

선화 기록 목표는 사진의 피사체와 구도를 유지하는 `style1` 흰 배경 컬러 선화다. 원본 RGB는 선 마스크에만 입히고 색면을 만들지 않는다. 5색 양자화, 외곽선 굵게, 내부선 제거, 거친 인쇄, 장면 재배치, 확산 모델은 사용하지 않는다. `palette1`~`palette5`는 별도 metadata이며 선화의 색 수 제한이 아니다. 기존 `Stamp`/`Ink` 기술 ID는 호환할 수 있지만 UI와 기록 표현은 선화 기준으로 갱신한다.


## 상세 이미지와 AI 메모 편집 — 2026-09-09 후속 요청

- 상세의 큰 선화를 누르면 사진 전용 모달로 연다. 최초 1배에서 전체 이미지를 비율대로 중앙에 표시하고 핀치 확대·축소와 확대 상태 이동, 확대·축소·원래 크기 버튼을 제공한다. 범위는 1~4배이며 닫으면 기존 상세로 복귀한다. 재진입하면 1배로 초기화한다. 저장 후 원본을 복원하거나 새로 생성하는 기능은 아니다.
- 문구 편집에는 직접 작성과 AI 제안 수정에 공통으로 쓰는 “기록 글” 입력칸 하나를 둔다. AI 문구는 기존 글 끝에 추가하며 요청 이후 직접 수정한 글에 늦은 결과를 반영하지 않는다. 요약·상세·내보내기에서도 한 본문으로 읽는다. 이전 분리 기록의 두 원문은 보존하고 AI 원문 메타데이터는 유지한다.
- “비우기”로 직접 작성할 수 있으며 비운 메모를 재진입 시 자동으로 채우지 않는다. 이미 쓴 글의 대체는 확인 또는 되돌리기 수단을 제공한다. 생성 중 입력한 메모와 생성 실패 전 초안은 보존한다.
- 시트 적용은 초안만 변경하고 최종 저장은 기존 기록 저장 흐름을 따른다. AI 문구 생성은 사용자가 요청할 때만 시작하며 새 모델 연결 여부는 프로젝트 현황에서 구분한다.

- 비활성 CTA도 버튼 윤곽과 글자를 식별할 수 있어야 한다. 배경 `#DDD6C9`, 테두리 `#7F776A` 1px, 글자 `#59564F`로 구성한다. 글자 대비 5.07:1, 비활성 배경 대비 테두리 3.06:1을 확인했다. 활성 CTA는 `#294B63`/`#FFFDFA`를 유지한다. 비활성 상태의 동작 차단과 상태 표시는 유지하고 색만으로 설명하지 않는다.
