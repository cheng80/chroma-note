# Chroma Note Stamp Record 디자인 brief

> 2026-09-09 · Stamp 화면 설계. [제품 명세](../01_PRODUCT_SPEC.md)의 SR-SCREEN/SR-FR이 동작 정본이다. [새 Pen 디자인](../../design/README.md)의 정적 검증을 수행했으며 실제 앱 UI 검증은 남아 있다.

공식 앱 5개의 조사 근거와 단계별 시각 결정은 [감성 디자인 리서치·Pen 개선 기준](design.md)에 정리한다. 이 brief는 공통 화면 동작·상태 계약을 유지한다. 기준 뷰포트는 `390x844`, `360x800`, `320x640`이며, 시각 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)을 참조한다.

## 1. 시각 방향과 정보 우선순위

“Photos to Stamps, Moments to Stories”의 사진→Stamp 변환 경험을 중심으로 한다. 여행 전용이나 카메라 앱으로 한정하지 않는다. 사진을 가져온 뒤 실제 장면과 색 관계가 남은 절제된 컬러 잉크/판화 결과를 모으는 감상 경험이다.

우선순위: Stamp → 기록 날짜/짧은 메모 → AI 글·태그 → 대표색. UI를 우표 구멍·손글씨·종이 패턴으로 모두 장식하지 않는다. Stamp 자체의 원본 색 관계를 살린 절제된 컬러 잉크 표현과 밝은 종이 여백으로 결과물이 돋보이게 한다. 색상칩은 Stamp보다 앞서는 주 오브젝트로 쓰지 않는다.

첨부 포스터는 원본→목표 출력 쌍이며, 확보한 원본과 목표 출력을 평가 기준으로 삼는다. 모델 선정은 원본 구조의 주요 피사체·사람 수·배치, 목표 컬러 Stamp 유사도, 소요 시간의 절충으로 평가하며 완벽한 픽셀 복제는 목표가 아니다. 평가 도구·결과는 [SMOKE_RESULTS](../../experiments/model-selection/SMOKE_RESULTS.md)에 중앙 기록하고 앱 실사용 결과 확인 UI와 구분한다. 제한된 원본 컬러 색면, 검정 잉크 윤곽, 작은 종이 노출 공백, 거친 인쇄 질감을 참고하며 수채화나 매끈한 벡터 표현은 목표가 아니다. 포스터의 사진·도장 배치 비율과 4:3 구성은 앱 요구사항이 아니다.

AI 원본/임포트/Ink/Supabase 제품 계약은 유지한다. 원본은 비교와 로컬 처리에만 쓰고, 서버 Record에는 업로드하지 않는다.

인포그래픽은 분위기와 원본/결과 비교 방향을 참고한다. 그림 안의 촬영·GPS·지도·프로필·공유·다중 스타일 선택은 Phase 1에 넣지 않는다. 그 이미지의 카페 장면은 AI 품질 benchmark 원본이 아니다.

## 2. 내비게이션과 화면 조합

기본 진입은 인증 후 Book이다. 헤더에 설정을 두고, 하단 5탭은 만들지 않는다. Book의 누적 목록은 스크롤할 수 있지만 화면 전체를 기능 설명으로 길게 늘이지 않는다. 새 기록은 Book 위에서 전체화면 2단계로 열고, 닫을 때 로컬 초안을 보관한다.

| 단계/영역 | surface | trigger | result |
|---|---|---|---|
| 인증 | 전체화면 | 이메일·OTP 입력 | 세션 복원 후 Book 진입 |
| Book | 한 화면 요약 + 누적 목록 | 사진 가져오기·초안 재개·필터·Record 선택 | 빈 목록·0결과·부분 캐시·조회 실패를 구분 |
| 처리 | 전체화면 | 사진 선택 후 자동 진행·취소 | 색·VLM·Stamp 결과와 실패 단계 보존 |
| 새 기록 1/2 | 전체화면 비교 | 후보 확인 checkbox → “내용 확인” | 확인 전 다음/저장 차단, 후보 교체 후 재확인 |
| 새 기록 2/2 | 전체화면 기록 요약 | 글/태그·메모·날짜/장소·색 행 열기 | 시트 “적용”은 로컬 초안, “저장하기”는 서버 확정 |
| 상세 | 큰 Stamp + 전체 글·태그 | 이미지 확대·더보기 | 내보내기·편집·삭제 진입 |

## 3. 새 기록과 Book 상세

Book은 폰 기본 2열, 좁은 폭·큰 글씨에서 1열이며 태블릿은 최소 카드 폭 200과 가용 공간에 따라 3~4열이다. Stamp 전체를 contain으로 보여 주고 날짜·짧은 메모를 묶는다. 첫 화면에 더 넣기 위해 글씨·터치 영역을 줄이거나 사진 속 인물을 자르지 않는다. 즐겨찾기는 이름 있는 48×48 이상의 조작으로 제공한다.

새 기록 1/2는 원본과 Stamp를 같은 비율로 비교한다. 폰에서는 탭 또는 명시 버튼으로 전환하고, 원본 확대는 별도 전체화면으로 연다. 결과 확인 checkbox를 선택하기 전에는 “내용 확인” CTA를 진행할 수 없다. 후보 재생성·후보 교체·사진 교체는 확인 상태를 해제한다. Stamp는 원본 주요 색과 색 관계를 살린 절제된 컬러 Ink 1종이며, 원본은 서버에 저장하지 않는다.

새 기록 2/2는 큰 Stamp, 날짜·장소, 내 메모·AI 표시 글·모든 태그를 하나의 종이색 기록 카드로 함께 보여 준다. 긴 글은 화면 내부에서 세로 스크롤하고 생략하지 않는다. 아래 편집 행은 날짜/장소·AI 글/태그·메모·색 시트를 열며 저장 CTA는 고정한다. AI 문구는 사용자가 명시 생성한 뒤 가져오기·수정·비우기를 선택하고 기존 메모를 자동으로 덮어쓰지 않는다.

저장된 상세도 같은 기록 카드를 사용해 Stamp와 글·태그 전체를 함께 읽게 한다. 사진은 확대 팝업으로 열고 편집은 기존 시트를 사용한다. 더보기의 내보내기는 같은 카드의 PNG 미리보기 → 갤러리에 저장으로 이어진다. 버튼·워터마크·임의 기록 번호·원본 사진은 출력하지 않는다. 권한은 저장할 때만 요청하고 실제 사진 저장 뒤 성공을 표시한다.

## 4. 시트·모달과 상태 보존

- 시트는 메모(큰 높이·키보드), 날짜/장소(중간 높이·네이티브 달력), AI 글/태그(큰 높이), 필터(중간 높이), 색 읽기로 역할을 고정한다. 시트 중첩은 금지한다. 날짜 선택은 현재 시트 안의 네이티브 달력 영역으로 전환하고 완료 후 날짜/장소로 복귀한다.
- 필터 적용 전 변경은 로컬 임시값이다. 취소하면 기존 필터를 유지한다. 시트에 변경 내용이 있으면 바깥 탭·드래그·뒤로가기로 silent discard하지 않는다.
- 기본 닫기는 초안을 보관한 뒤 닫기다. “취소”는 이번 시트 편집만 되돌린다. 영속 저장 실패를 보존 성공처럼 표시하지 않는다.
- 삭제·교체·폐기는 중앙 확인 모달이다. Android back은 키보드 닫기 → 현재 시트 닫기 순서를 따르며, 변경 초안은 보존한다. Reduce Motion에서는 전환을 줄인다.
- 필수값이 없으면 하단 CTA를 진행시키지 않고 이유를 텍스트로 표시한다. 하단 CTA는 키보드·홈 영역에 가리지 않는다.

## 5. 처리·오류·보존되는 데이터

모델은 앱 첫 화면을 표시한 뒤 미리 준비한다. 준비 중에도 Book을 둘러볼 수 있고, 새 기록 진입부에 “스탬프를 준비하고 있어요”를 짧게 표시한다. 매 실행마다 전체화면 대기나 모달을 강요하지 않는다. 이미 준비됐다면 상태 문구를 없애고 바로 사진을 고를 수 있다. 준비가 끝나기 전에 사진을 고르면 초안을 보존하고 “준비가 끝나면 시작할게요”와 취소를 제공한다. 실패한 경우에만 재시도·돌아가기를 제시한다. 메모리에서 해제됐다가 다시 준비하는 경우도 같은 흐름을 사용하며 가짜 진행률·시간 약속은 표시하지 않는다. 모든 안내·취소 버튼은 safe area 안에 둔다.

| 상황 | 문구 기본안 | 행동 / 보존 |
|---|---|---|
| 빈 Book | 첫 순간을 스탬프로 남겨보세요 | 사진 가져오기 |
| 선택 취소 | 별도 오류 팝업 없음 | Book 또는 입력 확인으로 복귀 |
| 클라우드 사진 대기 | 사진을 가져오고 있어요 | 취소; 기존 초안 보존 |
| 모델 없음 | 스탬프 변환에 필요한 파일을 받아 주세요 | 용량 확인·다운로드·나중에 |
| VLM 실패 | 사진 설명을 만들지 못했어요 | 다시 시도·AI 설명 없이 계속 |
| Stamp 실패 | 스탬프를 만들지 못했어요. 작업은 남아 있어요 | 다시 시도·초안으로 나가기 |
| 원본 보존 의심 | 원본과 다른 부분이 있나요? | 다시 만들기·사진 바꾸기 |
| 오프라인 저장 | 이 기기에 보관했어요. 연결되면 저장을 이어갈게요 | 저장 대기 표시, 중복 성공 toast 없음 |
| 서버 성공 | Book에 저장했어요 | 상세 열기 |
| 초안 재개 | 만들던 스탬프가 있어요 | 이어서 만들기·버리고 새로 만들기 |
| 저장된 기록의 원본 없음 | 원본은 보관하지 않아요. 새로 만들려면 사진을 다시 가져와 주세요 | 사진 가져오기 |
| 수정 충돌 | 다른 기기에서 기록이 바뀌었어요 | 최신 내용 확인·내 수정 다시 적용 |
| 삭제 중 | 기록을 삭제하고 있어요 | 정리 재시도; 완료로 오인하지 않음 |
| 로그아웃 전 미저장 | 이 기기의 미저장 작업은 로그아웃하면 지워져요 | 저장 후 나가기·폐기 후 나가기·취소 |

처리 취소가 완료된 이전 단계를 지우는 것은 아니다. 초안 저장 자체가 실패한 경우 “작업은 남아 있어요”를 사용하지 않는다. 무한 spinner·가짜 백분율·거짓 ETA를 표시하지 않는다.

빈 Book에는 기존 Ink 이미지와 “이런 모습으로 남아요” 안내를 배치하고 사진 가져오기를 안내한다. 사용자 기록이나 실제 모델 변환 결과로 표시하지 않는다.

## 6. 시각 기본값과 접근성

2026-09-09 후속 요청으로 절제된 머테리얼 표면을 사용한다. Book 카드와 주요 행동에는 낮은 그림자, 바텀시트와 확인 모달에는 높은 그림자를 적용한다. 기존 종이색·잉크색·간격·contain 중앙 정렬을 유지하고, 모션은 무료 요소와 현재 네이티브 기능을 사용하며 동작 줄이기 설정을 따른다. 제품 화면에서 시연·데모·구현 상태 안내는 제거하고, 실제 연결과 검증 상태는 프로젝트 현황에 기록한다.

paper #F7F3EA, surface #FFFDFA, ink #292823를 사용한다. 여기서 `ink #292823`는 UI 텍스트 토큰이며 결과 Stamp 이미지의 색상 제약이 아니다. 결과 Stamp는 원본 주요 색과 색 관계를 살린 절제된 컬러 잉크 도장으로 읽혀야 한다. 현재 Pen에서 단색 배경의 텍스트 대비를 검사했으며 색 변경·실제 이미지 배경·네이티브 구현에는 다시 확인이 필요하다. 앱 본문은 시스템 한/영 글꼴을 우선하며, 영문 로고·날짜에 제한적인 serif를 쓸 수 있다. Pen 표현용 Noto Sans KR/Libre Baskerville이 앱 폰트 패키지 설치를 요구하는 것은 아니다.

본문 16/24 논리 픽셀, 보조 14/20, 작은 UI 최소 12를 기본값으로 삼는다. 원본 그림의 장식 글씨를 제품 본문 크기로 복제하지 않는다. 모든 조작 48×48, 확대 글씨 200%에서 줄바꿈/스크롤. 상태는 색+텍스트/아이콘으로 나타낸다.

safe area는 모든 화면·시트·중앙 확인 모달에 필수다. 실제 OS runtime의 top/bottom/left/right inset을 적용하고, `390x844` fixture에서는 status bar 포함 top 62, bottom 34를 기준으로 하며 노치 가로 좌우 inset을 반영한다. iOS 홈 인디케이터, Android 제스처, Android 3버튼 내비게이션을 각각 처리한다. header와 footer를 분리하고 하단 CTA는 홈 영역 위에 둔다. 키보드가 보일 때 높이와 inset을 이중 차감하지 않으며, 실제 runtime 값으로 확인한다. 화면 배경과 scrim만 안전영역을 침범할 수 있고 인터랙션 콘텐츠는 침범할 수 없다.

사진/Stamp 접근성 설명은 사용자 확인 장면 또는 중립적 “스탬프 이미지”다. 미검증 AI 환각을 접근성 설명으로 사실처럼 반복하지 않는다. 처리 완료·오류만 적절히 알리고 초당 진행 변경을 계속 읽지 않는다. Reduce Motion에서는 전환을 최소화하며 다운로드/저장을 모션만으로 표현하지 않는다.

검증 viewport: `390x844`, `360x800`, `320x640`, 태블릿 세로·가로, 한/영, 200% 글씨, 키보드, VoiceOver/TalkBack. 실제 런타임 safe area와 키보드 값, header/footer 분리, 하단 CTA 위치, 중앙 모달의 스크린리더 포커스와 닫힌 뒤 복귀를 확인한다. 정적 그림과 네이티브 동작은 별도로 검사한다.

## 7. 산출물과 검증 상태

현재 산출물은 이 문서, [리서치·개선 기준](design.md)과 [Pen·PNG](../../design/README.md)다. 정적 Pen 검증 범위와 시각 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)을 참조한다. 이 brief의 실제 앱 UI, 런타임 safe area, 키보드, 스크린리더 동작은 구현 검증으로 분리한다.

사용자의 새 디자인 요청에 따라 모델 검증과 분리해 fixture로 작성했다. 사진과 Stamp는 각각 생성한 디자인 예시이며 실제 변환·원본 보존 결과가 아니다. 모델 품질 확인 후 실제 출력으로 교체해 다시 검증한다. 앱 UI, 키보드·스크린리더·실기기 safe area 접근성 검증은 NOT_RUN이다.

모델 출력의 현재 최소 품질은 사용자가 수용한 `JSON · 512 · seed 17`이다. 원래 ChatGPT 도장은 스타일 참고로 유지하되, 작은 장식·의상 잔무늬를 더 단순화하는 방향이다. 품질 수용과 현 모델의 속도 채택은 별개이며 실측·기준 자산은 [실험 결과](../../experiments/model-selection/SMOKE_RESULTS.md)에 기록한다.

Stamp 목표는 사진의 주요 특징을 추려 재구성한 컬러 도장이다. 인물 수·대표 사물·핵심 관계를 남기되 주변 장식 생략·장면 압축·여백 재배치를 허용한다. 원본 픽셀과 세부 위치 일치를 강제하지 않는다.


## 상세 이미지와 AI 메모 편집 — 2026-09-09 후속 요청

- 상세의 큰 Stamp를 누르면 사진 전용 모달로 연다. 최초 1배에서 전체 이미지를 비율대로 중앙에 표시하고 핀치 확대·축소와 확대 상태 이동, 확대·축소·원래 크기 버튼을 제공한다. 범위는 1~4배이며 닫으면 기존 상세로 복귀한다. 재진입하면 1배로 초기화한다. 저장 후 원본을 복원하거나 새로 생성하는 기능은 아니다.
- 메모 시트에서 AI 글을 생성하고 제안을 확인한 뒤 “내 메모로 가져오기”로 편집을 시작한다. 기존 AI 글이 있으면 가져와 수정·추가할 수 있다. AI 원문과 사용자 메모는 별도 필드로 유지한다.
- “비우기”로 직접 작성할 수 있으며 비운 메모를 재진입 시 자동으로 채우지 않는다. 이미 쓴 글의 대체는 확인 또는 되돌리기 수단을 제공한다. 생성 중 입력한 메모와 생성 실패 전 초안은 보존한다.
- 시트 적용은 초안만 변경하고 최종 저장은 기존 기록 저장 흐름을 따른다. AI 문구 생성은 사용자가 요청할 때만 시작하며 새 모델 연결 여부는 프로젝트 현황에서 구분한다.

- 비활성 CTA도 버튼 윤곽과 글자를 식별할 수 있어야 한다. 배경 `#DDD6C9`, 테두리 `#7F776A` 1px, 글자 `#59564F`로 구성한다. 글자 대비 5.07:1, 비활성 배경 대비 테두리 3.06:1을 확인했다. 활성 CTA는 `#294B63`/`#FFFDFA`를 유지한다. 비활성 상태의 동작 차단과 접근성 상태는 유지하고 색만으로 설명하지 않는다.
