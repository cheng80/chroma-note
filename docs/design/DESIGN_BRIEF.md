# Chroma Note Stamp Record 디자인 brief

> 2026-09-09 · Stamp 화면 설계. [제품 명세](../01_PRODUCT_SPEC.md)의 SR-SCREEN/SR-FR이 동작 정본이다. [새 Pen 디자인](../../design/README.md)의 정적 검증을 수행했으며 실제 앱 UI 검증은 남아 있다.

## 1. 시각 방향과 정보 우선순위

“Photos to Stamps, Moments to Stories”의 사진→Stamp 변환 경험을 중심으로 한다. 여행 전용이나 카메라 앱으로 한정하지 않는다. 사진을 가져온 뒤 실제 장면이 남은 잉크/판화 결과를 모으는 감상 경험이다.

우선순위: Stamp → 기록 날짜/짧은 메모 → AI 글·태그 → 대표색. UI를 우표 구멍·손글씨·종이 패턴으로 모두 장식하지 않는다. Stamp 자체의 잉크 표현과 밝은 종이 여백으로 결과물이 돋보이게 한다. 색상칩은 Stamp보다 앞서는 주 오브젝트로 쓰지 않는다.

인포그래픽은 분위기와 원본/결과 비교 방향을 참고한다. 그림 안의 촬영·GPS·지도·프로필·공유·4스타일은 Phase 1에 넣지 않는다. 그 이미지의 카페 장면은 AI 품질 benchmark 원본이 아니다.

## 2. 내비게이션

기본 진입은 인증 후 Book. 헤더에 설정, 화면의 주 행동은 “사진 가져오기”. 기능이 없는 하단 5탭은 만들지 않는다. 새 기록 흐름은 Book 위에서 열리고 이탈하면 초안 상태를 남긴다.

| 화면 | 배치/행동 | 이어지는 상태 |
|---|---|---|
| SR-SCREEN-001 인증 | 이메일, OTP 입력, 재발송, 수정; 키보드 영역 확보 | 복원/전송/검증 중, 만료·제한·오프라인 |
| SR-SCREEN-002 Book | 날짜순 Stamp grid, 초안/저장 대기 안내, 필터, 가져오기 | 빈 Book, 0결과, 부분 캐시, 읽기 실패 |
| SR-SCREEN-003 사진 입력 | OS 선택기 → 전체 사진·날짜 확인, 다른 사진, 계속 | 취소·다운로드·손상·크기/공간 제한 |
| SR-SCREEN-004 처리 | 사진 작은 미리보기, 현재 단계 문구, 취소 | 모델 준비/분석/변환, 생략 가능한 VLM 실패 |
| SR-SCREEN-005 확인/메모 | 동일 비율 원본/Stamp, AI 글과 내 메모 별도, 저장 | 후보/필수값/확인/수정/대기/실패 |
| SR-SCREEN-006 상세/편집 | Stamp 중심, 보조 메타데이터, 변경 저장, 삭제 | 이미지 누락·오프라인·충돌·삭제 중 |
| SR-SCREEN-007 설정 | 언어·모델 관리·데이터 안내·로그아웃·계정 삭제 | 모델 다운로드·미저장 경고·삭제 재인증 |

## 3. Book과 상세

폰은 기본 2열 Stamp grid, 좁은 폭/큰 글씨에서는 1열로 줄인다. 태블릿은 최소 카드 폭 200과 실제 가용 공간으로 3~4열을 선택한다. 첫 viewport에 몇 장을 강제로 넣기 위해 글씨나 터치 영역을 줄이지 않는다.

카드는 Stamp 전체를 contain으로 보여 주고 날짜·짧은 메모를 묶는다. 사람이 있는 그림을 grid 크기에 맞춰 잘라내지 않는다. 즐겨찾기는 이름 있는 조작이며 작은 하트만 터치 표적으로 두지 않는다. 색상칩은 장식/보조정보이며 성공·에러 상태색이 아니다.

상세는 Stamp → 기록 날짜/장소 → AI 글 → 내 메모 → 태그/대표색 순이다. 화면 읽기 순서도 같다. AI 표시 글이 숨김이면 AI 섹션을 생략하고 “내 메모”는 별도 유지한다. 수정 때만 입력 UI를 연다.

저장 완료 Record의 상세에는 원본이 없다. 원본/Stamp 비교·재생성 버튼은 저장 전 확인 화면에만 둔다. 새로 만들기를 안내할 때 원본을 서버에서 복원할 수 있다는 인상을 주지 않는다.

## 4. 비교와 편집

- 폰은 원본/Stamp 탭, 태블릿은 같은 크기 2열 비교를 기본으로 한다. 각 이미지의 fit/방향을 맞춘다.
- 확대는 별도 버튼과 스크롤을 지원한다. 두 손가락이나 드래그 슬라이더 하나만으로 핵심 비교를 제공하지 않는다.
- 최초 Stamp는 Ink 1종. Color/Mono/Sketch의 잠긴 탭·광고·결제 버튼을 선행 배치하지 않는다.
- “원본과 달라진 부분이 없는지 확인해 주세요”와 비교 수단 뒤에 결과 확인 checkbox를 둔다. 새 후보 채택/사진 교체 시 확인을 해제한다.
- AI 글 영역에는 “AI가 쓴 글”, 편집 시 “AI 글을 수정함”. 내 메모는 “내가 기억하고 싶은 이야기” placeholder, AI 글 자동 복사 없음.
- 삭제/사진 교체/재생성은 바뀌는 대상과 유지되는 메모를 확인 문구에 정확히 쓴다.
- “저장하기”는 하단 안전영역 위에서 키보드에 가려지지 않게 한다. 필수 결과 없으면 비활성 이유를 텍스트로 표시한다.

## 5. 처리·오류·보존되는 데이터

| 상황 | 문구 기본안 | 행동 / 보존 |
|---|---|---|
| 빈 Book | 첫 사진을 스탬프로 남겨보세요 | 사진 가져오기 |
| 선택 취소 | 별도 오류 팝업 없음 | Book 또는 입력 확인으로 복귀 |
| 클라우드 사진 대기 | 사진을 가져오고 있어요 | 취소; 기존 초안 보존 |
| 모델 없음 | 스탬프를 만들려면 모델 다운로드가 필요해요 | 용량 확인·다운로드·나중에 |
| VLM 실패 | 사진 설명을 만들지 못했어요 | 다시 시도·AI 설명 없이 계속 |
| Stamp 실패 | 스탬프를 만들지 못했어요. 작업은 남아 있어요 | 다시 시도·초안으로 나가기 |
| 원본 보존 의심 | 원본과 다른 부분이 있나요? | 다시 만들기·사진 바꾸기 |
| 오프라인 저장 | 이 기기에 보관했어요. 연결되면 저장을 이어갈게요 | 저장 대기 표시, 중복 성공 toast 없음 |
| 서버 성공 | Book에 저장했어요 | 상세 열기 |
| 초안 재개 | 만들던 스탬프가 있어요 | 이어서 만들기·버리고 새로 만들기 |
| 저장된 기록의 원본 없음 | 원본은 보관하지 않아요. 새로 만들려면 사진을 다시 가져와 주세요 | 사진 가져오기 |
| 수정 충돌 | 다른 기기에서 기록이 바뀌었어요 | 최신 내용 확인·내 수정 다시 적용 |
| 삭제 중 | 기록을 삭제하고 있어요 | 정리 재시도; 완료로 오인하지 않음 |
| 로그아웃 전 미저장 | 이 기기의 미저장 작업은 로그아웃하면 지워져요 | 저장 후 나가기·폐기 후 나가기·취소 |

처리 취소가 완료된 이전 단계를 지우는 것은 아니다. 초안 저장 자체가 실패한 경우 “작업은 남아 있어요”를 사용하지 않는다. 무한 spinner·가짜 백분율·거짓 ETA를 표시하지 않는다.

## 6. 시각 기본값과 접근성

paper #F7F3EA, surface #FFFDFA, ink #292823를 사용한다. 현재 Pen에서 단색 배경의 텍스트 대비를 검사했으며 색 변경·실제 이미지 배경·네이티브 구현에는 다시 확인이 필요하다. 앱 본문은 시스템 한/영 글꼴을 우선하며, 영문 로고·날짜에 제한적인 serif를 쓸 수 있다. Pen 표현용 Noto Sans KR/Libre Baskerville이 앱 폰트 패키지 설치를 요구하는 것은 아니다.

본문 16/24 논리 픽셀, 보조 14/20, 작은 UI 최소 12를 기본값으로 삼는다. 원본 그림의 장식 글씨를 제품 본문 크기로 복제하지 않는다. 모든 조작 48×48, safe area 네 방향, 확대 글씨 200%에서 줄바꿈/스크롤. 상태는 색+텍스트/아이콘으로 나타낸다.

사진/Stamp 접근성 설명은 사용자 확인 장면 또는 중립적 “스탬프 이미지”다. 미검증 AI 환각을 접근성 설명으로 사실처럼 반복하지 않는다. 처리 완료·오류만 적절히 알리고 초당 진행 변경을 계속 읽지 않는다. Reduce Motion에서는 전환을 최소화하며 다운로드/저장을 모션만으로 표현하지 않는다.

검증 viewport: 320/360/390 폰, 태블릿 세로·가로, 한/영, 200% 글씨, 키보드, VoiceOver/TalkBack. 정적 그림과 네이티브 동작은 별도로 검사한다.

## 7. 산출물과 검증 상태

현재 산출물은 이 문서와 [Pen·PNG](../../design/README.md)다. 7개 화면 그룹의 정상·실패·복구·인증·모델 준비를 28개 화면 변형과 6개 시스템 보드로 표현했다. 공통 컴포넌트는 13개이며 정적 대비·레이아웃·조작 영역 검사를 수행했다. 검사 범위와 수치는 프로젝트 현황에 기록한다.

사용자의 새 디자인 요청에 따라 모델 검증과 분리해 fixture로 작성했다. 사진과 Stamp는 각각 생성한 디자인 예시이며 실제 변환·원본 보존 결과가 아니다. 모델 품질 확인 후 실제 출력으로 교체해 다시 검증한다. 앱 UI, 키보드·스크린리더·실기기 접근성 검증은 NOT_RUN이다.
