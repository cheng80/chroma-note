# Chroma Note 감성 디자인 리서치와 Pen 개선 기준

> 조사 기준일: 2026-09-09 (Asia/Seoul). 대상은 공식 홈페이지 또는 개발사 App Store 설명과 공식 스크린샷이다. 제품 설명에 적힌 기능, 스크린샷에서 직접 본 시각 요소, Chroma Note에 대한 해석을 구분한다.


**방향: 한 장의 사진을, 다시 펼쳐 보고 싶은 기록으로.** 감성을 추가 기능이나 장식 개수로 만들지 않고 선화의 존재감, 종이 여백, 짧은 개인 문구로 만든다.

편집 대상은 Pen 메인 화면이며, 이 문서는 공식 사례의 근거와 이번 시각 결정·반영 위치를 관리한다. 기능·상태는 [제품 명세](../01_PRODUCT_SPEC.md), 공통 화면 계약은 [디자인 brief](DESIGN_BRIEF.md), 실행 상태는 [현황](../03_PROJECT_STATUS.md)이 정본이다. Pen은 저장 완료 상태이며 루트 60개·재사용 컴포넌트 15개·placeholder 0개를 [Pen 안내](../../design/README.md)와 현황에서 확인한다. 앱 UI 반영·런타임 검증은 별도다.

## 조사 범위와 판정 기준

- 제품 설명은 각 개발사·서비스가 공식적으로 명시한 기능과 가치 제안만 기록한다.
- 시각 관찰은 2026-09-09에 각 공식 App Store 페이지의 첫 번째 제품 스크린샷을 직접 열어 확인한 범위만 단정한다. 스크린샷은 마케팅 이미지이므로 실제 모든 화면·동작의 증거로 확장하지 않는다.
- 감성 장치는 공식 기능에서 사용자가 느낄 수 있는 경험을 해석한 것이다. 해석은 제품 사실과 문장을 분리한다.
- 적용·제외는 현재 Chroma Note 계약에만 연결한다. 사진 임포트, 흰 배경 `style1` 컬러 선화, Book 2열, 저장 후 원본 없음, AI 글과 내 메모 구분을 유지하며 새 기능을 기획하지 않는다.

## 채택한 디자인 방향

- Book 초안 안내는 기록 아래의 짧은 보조 버튼으로 압축한다. 선화를 먼저 보여 주고, 사진 가져오기에서 기존 초안의 처리 선택을 여는 계약은 유지한다.
- 2026-09-09 후속 요청에 따라 완전한 플랫 디자인에서 절제된 머테리얼 표면으로 전환한다. Book 카드는 밝은 surface와 낮은 그림자로 기록 단위를 묶고, 주요 버튼·시트·확인 모달은 역할에 따라 깊이를 구분한다. 결과 RGB 선화는 흰 배경에 표시하며 잉크 번짐·종이 질감은 넣지 않는다.
- AI 글은 박스 안에 가두지 않고 열린 여백 안에서 읽게 한다. `AI가 쓴 글` 표시는 유지하며 내 메모와 시각적으로 분리한다.
- 팔레트는 상세 하단의 보조 정보로 내린다. 대표색이 선화, 날짜, 글보다 앞서지 않게 한다.
- 빈 Book에는 기존 Ink fixture와 “이런 모습으로 남아요” 안내를 사용할 수 있다. 사용자가 저장한 Record처럼 보이게 하거나 새 기능으로 확장하지 않는다.
- 인증과 상세는 장식보다 입력·확인·편집이 먼저 보이는 간결한 편집형 화면으로 유지한다.

## 제품별 상세 관찰

### 1. Stampa: 우표의 물리적 문법을 기록 단위로 바꾸기

**공식 사실.** Stampa는 사진을 실제 우표처럼 톱니 모양으로 잘라 내고, 카메라 롤의 기존 사진도 사용할 수 있다고 설명한다. 컬렉션, 날짜별 달력, 스크랩북 캔버스와 종이 배경·장식 요소도 제공하며 데이터가 기기에 남는다고 명시한다. ([App Store 공식 설명](https://apps.apple.com/us/app/stampa-stamps-camera/id6762463647))

**직접 본 시각.** 공식 첫 스크린샷은 빨강 계열의 강한 배경과 `CAPTURE MOMENTS AS STAMPS`라는 큰 제목을 사용한다. 휴대폰 안쪽에는 톱니 모양 우표 프레임과 하단의 `Capture`, `Collection`, `Editor`, `Calendar`가 함께 보인다. ([공식 App Store 스크린샷](https://apps.apple.com/us/app/stampa-stamps-camera/id6762463647))

**디자인 해석.** 우표 외형은 장식이 아니라 “이 순간을 소장한다”는 완료 신호로 작동한다. 컬렉션과 달력은 사진을 많이 쌓는 것보다 모아 둔 기록을 다시 찾는 감정을 강화한다.

**Chroma Note 적용.** 선화를 단순 필터 결과가 아니라 Record의 주 오브젝트로 두고, Book 카드에서도 선화 전체가 먼저 보이게 한다. 날짜와 짧은 메모를 선화에 붙여 “수집된 기록”이라는 감각을 만든다.

**Chroma Note 제외.** 앱 내 카메라, 자유 배치 스크랩북, 와시 테이프·스티커·배경 선택, 여러 우표 모양을 추가하지 않는다. 이는 임포트 중심, Ink 1종, 화면 작업 UI와 결과물의 분리라는 현재 방향과 맞지 않는다. ([현재 설계 결정](../adr/ADR-003-stamp-record-direction.md))

### 2. NOMO CAM: 촬영 의식을 결과물의 물성으로 번역하기

**공식 사실.** NOMO CAM은 후처리보다 촬영에 집중하게 하며, 사진을 찍은 뒤 곡선·입자·먼지·빛샘·비네트·선명도·프레임 등의 무작위 아날로그 프리셋을 적용한다고 설명한다. ([App Store 공식 설명](https://apps.apple.com/us/app/nomo-cam-point-and-shoot/id1362548649))

**직접 본 시각.** 공식 첫 스크린샷은 검은 가죽 같은 질감의 카메라 본체와 둥근 렌즈, 작은 빨간 강조점을 화면 중앙에 배치한다. 제품 UI보다 실물 카메라의 표면과 조작부를 먼저 보여 주는 인상이다. ([공식 App Store 스크린샷](https://apps.apple.com/us/app/nomo-cam-point-and-shoot/id1362548649))

**디자인 해석.** NOMO의 감성은 “사진을 예쁘게 편집한다”보다 “카메라를 골라 찍고 결과를 기다린다”에 가깝다. 물리적 촉감의 환기는 사진을 일상적인 카메라 롤 이미지와 구별한다.

**Chroma Note 적용.** Chroma Note 결과는 사진의 원래 색을 선에만 남기는 흰 배경 컬러 선화다. 처리 중에는 단계 문구와 작은 원본 미리보기로 변환 의식을 만들되, 가짜 진행률이나 ETA는 사용하지 않는다. ([디자인 brief](DESIGN_BRIEF.md))

**Chroma Note 제외.** 카메라 촬영 화면, 랜덤 프리셋, 카메라 상점, 카메라별 잠금 UI는 제외한다. Chroma Note는 사진을 찍는 앱이 아니라 사진을 임포트해 선화 기록로 만드는 앱이다. ([현재 현황](../03_PROJECT_STATUS.md))

### 3. Dazz Cam: 한 번의 행동과 복고 기억을 연결하기

**공식 사실.** Dazz Cam은 한 번의 탭으로 빈티지 사진·영상을 만들고 별도 후편집 없이 결과를 얻는 방향을 설명한다. 80년대 필름 카메라를 참고하고 실제 필름 재고의 색과 질감을 샘플링했다고 밝히며, 여러 필름 포맷과 디지털 카메라 프로파일을 제공한다. ([App Store 공식 설명](https://apps.apple.com/us/app/dazz-cam-vintage-camera/id1422471180))

**직접 본 시각.** 공식 첫 스크린샷은 어두운 검정에서 빨강으로 흐르는 배경에 여러 복고 카메라를 배치하고, 상단에 `Analog Vintage Cameras / Photos and Videos`를 크게 쓴다. 기능 목록보다 카메라 컬렉션의 분위기를 먼저 전달한다. ([공식 App Store 스크린샷](https://apps.apple.com/us/app/dazz-cam-vintage-camera/id1422471180))

**디자인 해석.** 사용자가 조정값을 공부하지 않아도 결과가 즉시 생긴다는 낮은 마찰과, 특정 시대의 카메라를 떠올리게 하는 향수가 결합한다.

**Chroma Note 적용.** 임포트 → 처리 → 확인/메모의 경로를 짧게 유지하고, 결과 확인 화면에서 선화를 즉시 주인공으로 보여 준다. “한 번에 결과를 만난다”는 경험은 Ink 1종에서도 유지할 수 있다.

**Chroma Note 제외.** 사진·영상 모드, 135·120·토이·즉석·3D 등 포맷 선택, 여러 카메라·필름 탭, 세부 후편집을 만들지 않는다. Dazz의 제품 범위를 흉내 내는 것이 아니라 낮은 마찰이라는 원리만 참조한다.

### 4. Once Upon: 사진 묶음을 이야기와 물성으로 완성하기

**공식 사실.** Once Upon은 사진을 선택해 포토북을 만들고, 자동 채우기 또는 빈 책에서 시작하게 하며, 사진에 캡션을 추가할 수 있다고 설명한다. 공식 흐름은 날짜별 사진 선택, 표지 사진·제목·레이아웃·색 조정까지 보여 준다. ([공식 홈페이지](https://onceupon.photo/en-us), [App Store 공식 설명](https://apps.apple.com/us/app/once-upon-photo-book-creator/id1187208815))

**직접 본 시각.** 공식 첫 App Store 스크린샷은 크림색 여백 위에 `Turn your memories into photo books`라는 짙은 세리프 제목과 실제 포토북 이미지를 둔다. 화면 안의 기능보다 완성된 책의 존재감을 앞세운다. ([공식 App Store 스크린샷](https://apps.apple.com/us/app/once-upon-photo-book-creator/id1187208815))

**디자인 해석.** Once Upon은 사진을 선택하는 행위를 “정리 작업”에서 “한 권의 이야기 만들기”로 바꾼다. 자동 채우기와 빈 책의 선택은 시작 부담을 낮추면서도 최종 결과에 대한 소유감을 남긴다.

**Chroma Note 적용.** Book은 단순한 이미지 목록보다 날짜와 짧은 메모를 함께 읽는 감상 공간으로 구성한다. 기록을 저장한 뒤에는 선화와 텍스트가 조용한 종이 위에서 다시 보이게 하며, 첫 화면에 기능성 탭을 과도하게 늘리지 않는다. ([디자인 brief](DESIGN_BRIEF.md))

**Chroma Note 제외.** 포토북 주문, 인쇄, 결제, 협업 앨범, 표지 편집과 자유 레이아웃은 범위에 넣지 않는다. Chroma Note의 Book은 디지털 기록 탐색이며 출판 제품이 아니다.

### 5. Day One: 사적인 기록과 재방문의 리듬 만들기

**공식 사실.** Day One은 텍스트·사진·영상·그림·음성을 기록하고 `On This Day`, 달력, 태그, 즐겨찾기, 검색 필터, 지도 보기, 알림, 암호·생체 인증·종단간 암호화를 제공한다고 설명한다. ([공식 홈페이지](https://dayoneapp.com/), [App Store 공식 설명](https://apps.apple.com/us/app/day-one-daily-journal-diary/id1044867788))

**직접 본 시각.** 공식 첫 App Store 스크린샷은 밝은 청색 배경과 `My Journal` 목록 화면을 보여 주며, 화면 안에 `List`, `Calendar`, `Media`, `Map` 탭이 있다. 날짜, 짧은 제목, 본문 일부, 작은 미디어가 한 줄 기록으로 정리된다. ([공식 App Store 스크린샷](https://apps.apple.com/us/app/day-one-daily-journal-diary/id1044867788))

**디자인 해석.** Day One의 감성은 장식보다 사적인 지속성에서 나온다. 사용자가 과거의 같은 날을 다시 발견할 수 있다는 약속이 기록을 쌓는 이유가 된다.

**Chroma Note 적용.** 사진 처리에서 선화 변환과 태그 자동 생성을 결과와 함께 제공한다. AI 메모는 사용자가 명시적으로 생성을 요청한 경우에만 제안하고 자동 사진 처리에서는 만들지 않는다. AI 글에는 `AI가 쓴 글`을 붙이며 내 메모를 자동으로 채우거나 덮어쓰지 않는다. 상세 순서는 선화 → 날짜/장소 → AI 글 → 내 메모 → 태그/대표색을 유지하되, 내 메모는 큰 글자와 별도 여백으로 구분한다. ([디자인 brief](DESIGN_BRIEF.md))

**Chroma Note 제외.** 지도, 알림, 스트릭, 음성·영상, 자동 건강·서비스 연동, 여러 저널은 추가하지 않는다. 공식 기능을 모두 따라가는 대신 Chroma Note의 “선화 + 날짜 + 글” 계약만 남긴다.

## Chroma Note에 대한 구체적인 디자인 추천 5개

### 1. 선화를 카드의 장식이 아닌 기록 단위로 고정한다

Book과 상세의 첫 시선은 선화 전체 이미지에 둔다. Book 초안 안내는 기록 아래의 짧은 보조 버튼으로 두고, 밝은 카드 표면과 낮은 그림자로 기록 단위를 구분한다. 날짜와 짧은 메모는 같은 기록의 보조 정보로 묶고, 대표색 칩은 하단으로 내린다. Stampa의 우표형 결과와 Once Upon의 완성된 책을 참고하되, Chroma Note는 하나의 선화 기록 계약을 유지한다. ([Stampa](https://apps.apple.com/us/app/stampa-stamps-camera/id6762463647), [Once Upon](https://onceupon.photo/en-us), [현재 디자인 brief](DESIGN_BRIEF.md))

### 2. 임포트 직후의 비교를 가장 명확한 감정 전환으로 만든다

사진 가져오기 → 처리 → 원본/선화 확인 → 메모 → 저장 순서를 시각적으로 끊는다. 폰에서는 원본/선화 탭, 태블릿에서는 같은 크기의 2열 비교를 사용하고, 저장 후에는 원본이 다시 나타나지 않게 한다. Dazz의 낮은 마찰과 NOMO의 결과를 기다리는 의식을 임포트 흐름 안에서만 번역한다. ([Dazz Cam](https://apps.apple.com/us/app/dazz-cam-vintage-camera/id1422471180), [NOMO CAM](https://apps.apple.com/us/app/nomo-cam-point-and-shoot/id1362548649), [ADR-003](../adr/ADR-003-stamp-record-direction.md))

### 3. Book은 2열의 조용한 날짜순 수집함으로 유지한다

폰 기본은 2열 선화 grid이며, 카드 안에서 선화 전체·날짜·짧은 메모를 한 덩어리로 읽는다. 빈 Book에서는 기존 Ink fixture와 “이런 모습으로 남아요” 안내로 결과의 방향만 보여 주고, 저장된 기록처럼 취급하지 않는다. 날짜 필터와 즐겨찾기는 탐색을 돕되 별도 탭 바를 늘리지 않는다. Day One의 날짜 재방문을 참고하되 지도·스트릭·리마인더는 넣지 않는다. ([Day One](https://dayoneapp.com/), [디자인 brief](DESIGN_BRIEF.md))

### 4. AI 글과 내 메모의 목소리를 열린 여백에서 분리한다

AI 글은 박스 없이 여백 안에서 읽히게 하고 `AI가 쓴 글`을 붙인다. 사용자 입력에는 `내가 기억하고 싶은 이야기`를 사용하며 AI 글을 내 메모로 자동 복사하지 않는다. 상세 읽기 순서는 선화 → 날짜/장소 → AI 글 → 내 메모 → 태그/대표색으로 고정한다. Day One의 사적 기록 감각은 참고하되, Chroma Note의 AI 경계를 흐리지 않는다. ([Day One App Store 설명](https://apps.apple.com/us/app/day-one-daily-journal-diary/id1044867788), [디자인 brief](DESIGN_BRIEF.md))

### 5. 따뜻한 종이 여백과 Ink 1종만으로 물성을 만든다

`paper #F7F3EA`, `surface #FFFDFA`, `ink #292823`를 기본으로 쓰고, 색상칩은 상세 하단 보조 정보로만 둔다. `ink #292823`는 UI 텍스트 토큰이며 결과 선화의 색상 제약이 아니다. 현재 목표는 원본 RGB를 선 마스크에만 입힌 흰 배경 `style1` 컬러 선화다. 색면·5색 양자화·굵은 외곽선·내부선 제거·거친 인쇄·재배치·확산 모델은 적용하지 않는다. 포스터의 사진·도장 배치 비율과 4:3 구성은 앱 요구사항으로 옮기지 않는다. Stampa·NOMO·Dazz의 물성·복고 감각은 배경 장식이나 카메라 UI로 복제하지 말고 넓은 여백으로 압축한다. 인증과 상세는 입력·확인·편집이 먼저 보이는 간결한 화면으로 유지한다. 잠긴 스타일 탭, 결제 버튼, 다중 스타일 선택은 추가하지 않는다. ([시각 기본값](DESIGN_BRIEF.md), [ADR-003](../adr/ADR-003-stamp-record-direction.md))

현재 이미지 기준은 `style1`이다. 원본 RGB를 선 마스크에만 입혀 흰 배경에 표시하며, 색면·5색 양자화·굵은 외곽선·내부선 제거·거친 인쇄·잉크 번짐·종이 질감·재배치·확산 모델은 적용하지 않는다. `palette1`~`palette5`는 별도 metadata 색상 슬롯이며 선화 색 수 제한이 아니다. 디자인용 생성 원본 `generated-1788887280309.png`를 실제 출력 `design/images/lineart-style1-source-rgb.png`로 변환해 적용했다. 둘 다 사용자 사진이 아닌 디자인용 생성 자산이다.

## 스타일 선택

[UI 디자인 스타일 용어 정리](https://miny.tistory.com/30)는 미니멀리즘·글래스모피즘·뉴모피즘·스큐어모피즘 등의 용어를 참고하는 자료로만 사용한다. 공식 앱 조사 출처와 모델 품질·사용성 검증의 근거로 섞지 않는다.

메인 열람 화면은 절제된 머테리얼 디자인을 기본으로 선택한다. 필요한 정보와 주 행동을 한 화면에 두고, 여백·타이포그래피·선화 우선순위에 표면의 높이와 부드러운 그림자를 더해 계층을 만든다. 스큐어모피즘·잉크 번짐·종이 질감은 제품 화면과 RGB 선화에 적용하지 않는다. 결과물의 감상 맥락은 흰 배경·원본 RGB 선·여백으로 만들고 입력·탐색·저장 조작을 장식보다 앞세운다.

바텀시트는 불투명한 밝은 `surface`와 `scrim`으로 배경과 편집 계층을 분명히 한다. 화면 장식에 글래스모피즘이나 뉴모피즘을 기본 적용하지 않는다. 반투명 블러는 콘텐츠 대비와 safe area 판단을 흐릴 수 있고, 낮은 대비의 볼록·오목 그림자는 조작 가능성을 약화시킬 수 있으므로 현재 제품의 기본 표면에서 제외한다. safe area와 스크롤은 이 스타일 판단과 독립된 필수 사용성 계약으로 유지한다.

이 선택은 기존 AI 원본/임포트/Ink/Supabase 계약과 화면·시트 조합을 유지하는 시각 방향이며, 새 기능이나 새로운 스타일 선택 기능을 승인하는 내용이 아니다.

## 최신 화면 조합과 Pen 반영 기준

레이아웃 좌표·크기·정적 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)을 참조한다.

| 단계 | trigger | surface | result |
|---|---|---|---|
| 인증/Book | 세션 복원, 사진 가져오기, 초안 재개, 필터, Record 선택 | 인증 전체화면, Book 한 화면 요약 + 누적 목록 | 빈 목록·0결과·부분 캐시·조회 실패를 구분 |
| 처리 | 사진 선택 후 자동 진행, 취소, 재시도 | 처리 전체화면 | 색·VLM·Ink 결과와 실패 단계 보존 |
| 새 기록 1/2 | 결과 확인 checkbox 후 “내용 확인”; 후보 교체 시 재확인 | 전체화면 원본-선화 비교 | 확인 전 다음/저장 차단, 원본은 서버에 저장하지 않음 |
| 새 기록 2/2 | 글/태그·메모·날짜/장소·색 행 열기, “저장하기” | 전체화면 기록 요약 + 역할별 바텀시트 | 시트 “적용”은 로컬 초안, 명시 저장만 서버 확정 |
| 상세/편집 | “글 열기”, “더보기”, 기존 Record 편집, “변경 저장” | 상세 한 화면, 읽기·편집 시트, 중앙 확인 모달 | AI/메모 원문 분리, 삭제·교체·폐기 확인, 서버 확정 분리 |

시트는 메모(큰 높이·키보드), 날짜/장소(중간 높이·네이티브 달력), AI 글/태그(큰 높이), 필터(중간 높이), 색 읽기로 역할을 고정한다. 원본 확대는 전체화면이며 시트는 중첩하지 않는다. 날짜 선택은 현재 날짜 시트 안의 네이티브 달력 영역으로 전환하고 선택 후 날짜/장소 요약으로 복귀한다. 필터 적용 전 변경은 로컬 임시값이고 취소하면 기존 필터를 유지한다.

변경 내용이 있는 시트의 바깥 탭·드래그·뒤로가기는 silent discard하지 않는다. 기본 닫기는 초안 보관 후 닫기이고 취소는 이번 시트 편집만 되돌린다. Android back은 키보드 닫기 후 시트 닫기 순서다. 삭제·교체·폐기는 중앙 확인 모달로 처리한다.

모든 화면·시트·중앙 모달은 실제 OS safe area의 top/bottom/left/right inset을 강제한다. `390x844` fixture는 status bar 포함 top 62, bottom 34와 노치 가로 좌우 inset을 기준으로 삼고, iOS 홈 인디케이터·Android 제스처·3버튼 내비게이션을 각각 확인한다. header/footer를 분리하고 하단 CTA는 홈 영역 위에 둔다. 키보드 높이와 inset은 이중 차감하지 않으며 실제 runtime 값으로 확인한다. 화면 배경과 scrim만 침범할 수 있고 인터랙션 콘텐츠는 침범할 수 없다.

## 시각 규칙과 문구

- 2026-09-09 후속 결정: 카드·주요 버튼에는 낮은 그림자, 시트·중앙 확인 모달에는 높은 그림자를 적용한다. 그림자는 공통 토큰으로 관리하며 대비·48×48 조작·contain 중앙 정렬을 유지한다. 필드·본문 행마다 그림자를 반복하지 않는다.
- 제품 화면에는 “시연”, “데모”, 미구현·미연결 같은 개발 상태 안내를 넣지 않는다. 실제 연결·검증 상태와 한계는 프로젝트 현황에서 관리한다. 코드의 테스트 식별자는 이 문구 규칙의 대상이 아니다.

- 색: 기존 `paper #F7F3EA`, `surface #FFFDFA`, `ink #292823`, 주 행동 `#294B63`를 유지한다. 붉은 오류·삭제, 황색 저장 대기, 초록 성공의 의미도 유지한다.
- 글자: 브랜드만 Libre Baskerville 20, 한국어 제목 Noto Sans KR 28/1.35, 본문 16/1.5, 보조 14/1.5, 작은 정보 12/1.5. 상세와 저장 전 기록 카드에는 메모·AI 표시 글·태그 전체를 표시하고, 긴 내용은 해당 콘텐츠 영역만 스크롤한다. 앱 시스템 글꼴 우선 원칙은 그대로다.
- 공간: 화면 좌우 20, Book 섹션 20, 관련 글 8, 기본 그리드 12. 조작은 48×48 이상, 필드·행동에 필요한 테두리는 남긴다.
- 분위기: Book은 ‘다시 펼쳐 보는 순간’, 설명은 ‘사진 한 장, 오래 남길 이야기.’. 빈 화면은 ‘첫 순간을 선화로 남겨보세요’와 ‘걷던 길, 좋아하던 자리. 사진 한 장부터 가볍게 시작해요.’.
- 복구: ‘만들던 선화 1개 · 이어서 만들기’는 로컬 초안, ‘Book에 저장했어요’는 서버 확정이다. 저장 대기나 실패를 감성 문구로 덮지 않는다.
- 사진/선화는 기존 디자인 fixture 2개를 재사용한다. 다른 날짜의 동일 선화 반복은 레이아웃 예시이며 실제 기록이나 변환 성공의 근거가 아니다. 새 스타일·이미지 모델·기능은 추가하지 않았다.

## Scope and Coverage

정적 Pen은 현재 합의된 화면 조합과 역할을 시각화하는 보조 산출물이다. 기능 계약은 제품 명세, 공통 화면 동작은 디자인 brief, 실행 상태·화면 구성·흐름 보드 범위·시각 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)을 정본으로 삼는다.

| 영역 | 확인한 근거 | 결과 |
|---|---|---|
| Layout | `390x844`·`360x800`·`320x640` 기준 화면 역할과 한 화면 정보량 | 좌표·크기·시각 수치는 현황 참조; 전체 글·메모·태그는 유지하고 긴 콘텐츠 영역만 스크롤하며 화면 전체와 시트의 이중 스크롤은 금지 |
| Surface | 전체화면, 역할별 바텀시트, 중앙 확인 모달 | 시트 중첩 금지; 배경/scrim만 safe area 침범 |
| State | 비교 확인, 로컬 초안, 명시 서버 저장, 오류·복구 | 확인 전 차단·후보 교체 재확인·영속 저장 실패 보존 구분 |
| Accessibility | 48×48 조작, 200% 글씨, 키보드, VoiceOver/TalkBack | 실제 runtime safe area·모달 포커스/복귀·키보드 값은 NOT_RUN |
| Tone | 선화 중심, AI 글·내 메모 출처 분리, 종이 여백 | 사진·선화는 fixture 예시이며 모델 품질 증거가 아님 |

## Findings

| 중요도 | 위치 | 변경 전 문제 | 처리 |
|---|---|---|---|
| HIGH | 새 기록 전체 흐름 | 긴 한 페이지에 비교·입력·저장이 섞임 | 1/2 비교와 2/2 요약으로 분리하고 시트로 세부 편집 |
| HIGH | 저장 경계 | 시트 적용과 서버 저장 의미가 섞일 위험 | “적용”은 로컬 초안, “저장하기/변경 저장”만 서버 확정 |
| HIGH | safe area | OS별 inset과 키보드 처리가 정적 화면에 고정되지 않음 | 네 방향 실제 runtime inset, header/footer, 하단 CTA 계약을 명문화 |
| HIGH | 기록 정보 누락 | 선화와 글·태그를 함께 볼 수 없었음 | 같은 기록 카드에서 전체 표시하고 긴 내용은 스크롤 |

정적 문서에서 확정할 것은 정보 계층·표면 조합·상태 의미까지다. 실제 runtime inset, 키보드 높이, 모달 포커스와 복귀, Android back, 스크린리더 순서는 구현 검증으로 남긴다.

## Considered but Rejected

| 후보 | 채택하지 않은 이유 |
|---|---|
| UI 전체 우표 톱니·와시 테이프·기울어진 카드 | 선화보다 장식이 앞서고 작은 화면의 감상 면적이 줄어듦 |
| 필름/카메라 선택 탭 | 임포트와 Ink 1종이라는 현재 제품 범위를 벗어남 |
| 종이색·행동색 전면 교체 | 기존 색 대비가 충분하고 문제는 정보 밀도·배치에 있었음 |
| 저장 후 원본 비교 | 서버 확정 후 원본 정리 계약과 충돌 |

## Verification

- 기준 뷰포트 `390x844`·`360x800`·`320x640`에서 비교 1/2, 요약 2/2, 상세 요약, 역할별 시트의 정보 우선순위와 CTA 가시성을 확인한다.
- 모든 화면·시트·중앙 모달에 실제 OS top/bottom/left/right inset을 적용하고, `390x844` fixture의 status bar 포함 top 62·bottom 34, 노치 가로 좌우, iOS 홈·Android 제스처/3버튼을 확인한다.
- header/footer 분리, 하단 CTA의 홈 영역 이탈, 키보드 높이와 inset의 이중 차감 여부를 실제 runtime 값으로 확인한다. 인터랙션 콘텐츠가 safe area를 침범하지 않는지 확인한다.
- 결과 확인 checkbox 전 진행 차단, 후보 교체 후 재확인, 시트 적용과 서버 저장 분리, 필터 취소 보존, 변경 시 silent discard 방지, 중앙 확인 모달, Android back 키보드 우선, reduced motion을 확인한다.
- `NOT_RUN`: 실기기 UI, 실제 runtime safe area·키보드, VoiceOver/TalkBack 모달 포커스와 복귀, 동적 글씨 전환, 이미지 배경 대비, 모델 품질. 정적 Pen을 앱 기능 완료로 해석하지 않는다.
- 문서·저장본 최종 검증 결과와 시각 수치는 [프로젝트 현황](../03_PROJECT_STATUS.md)에 기록한다.

## Verdict

정적 Pen 디자인 범위에 한정한다. 메인 Pen은 저장 완료됐으며 루트 60개·재사용 컴포넌트 15개·placeholder 0개를 [Pen 안내](../../design/README.md)와 [프로젝트 현황](../03_PROJECT_STATUS.md)에서 확인한다. 앱 UI 반영·실제 runtime safe area·키보드·스크린리더·모델 품질은 별도 검증이며 Pen 저장 완료를 앱 기능 완료로 해석하지 않는다.

Approve

앱 시작 때 설치된 모델을 비동기로 준비하고 Book 이용을 막지 않는다. 새 기록 진입부의 짧은 준비 안내, 사진 선택 후 준비 대기·취소, 메모리 해제 후 재준비는 [디자인 brief](DESIGN_BRIEF.md)의 흐름을 따른다. 선화 출력의 기준은 위 `style1` 규칙과 실제 변환 자산으로 갱신한다. 과거 도장 목표는 현재 기준에서 삭제한다.


## 상세 이미지와 AI 메모 편집 — 2026-09-09 후속 요청

- 상세의 큰 선화를 누르면 사진 전용 모달로 연다. 최초 1배에서 전체 이미지를 비율대로 중앙에 표시하고 핀치 확대·축소와 확대 상태 이동, 확대·축소·원래 크기 버튼을 제공한다. 범위는 1~4배이며 닫으면 기존 상세로 복귀한다. 재진입하면 1배로 초기화한다. 저장 후 원본을 복원하거나 새로 생성하는 기능은 아니다.
- 문구 편집 시트에서 AI 글 생성·직접 수정, 내 메모 작성, 의미/분위기 태그 편집을 구역별로 제공한다. 생성 결과는 AI 글 필드에 바로 넣고, AI 원문과 사용자 메모는 별도 필드로 유지한다.
- “비우기”로 직접 작성할 수 있으며 비운 메모를 재진입 시 자동으로 채우지 않는다. 이미 쓴 글의 대체는 확인 또는 되돌리기 수단을 제공한다. 생성 중 입력한 메모와 생성 실패 전 초안은 보존한다.
- 시트 적용은 초안만 변경하고 최종 저장은 기존 기록 저장 흐름을 따른다. AI 문구 생성은 사용자가 요청할 때만 시작하며 새 모델 연결 여부는 프로젝트 현황에서 구분한다.

## 기록 카드와 이미지 내보내기

2026-09-09 사용자 후속 요청으로 요약의 작은 썸네일·4행 중심 및 상세의 원문 숨김 설계를 폐기한다. 저장 전과 저장 후 모두 큰 contain 선화, 날짜/장소, 전체 글/메모, 줄바꿈한 모든 태그를 함께 보여 준다. 편집 입력은 기존 시트로 분리한다. 더보기 → 내보내기 → 같은 카드 미리보기 → 갤러리에 PNG 저장을 제공한다. 출력은 크림 종이색 배경과 실제 기록 내용만 포함하며 원본·버튼·임의 기록 번호·워터마크를 포함하지 않는다. 긴 글은 이미지 높이를 늘려 담고 실패를 성공처럼 표시하지 않는다.
