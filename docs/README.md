## 문서 상태를 읽는 법

- **확정 방향**: 핸드오프 또는 기획 보완 인터뷰에서 사용자가 결정한 제품 경계. 별도 변경 요청 없이 뒤집지 않는다.
- **권장 / 설계 초안**: 원본이 제안한 구현 방식. 실제 구현 전에 환경과 요구를 확인해 구체화한다.
- **미정 / NEEDS-DECISION**: 원본에 답이 없거나 실제 구현 검증이 필요한 부분. 구현 완료로 간주하지 않는다.
- 제품 명세의 실패·예외와 완료 조건은 원본 핵심 흐름을 검증 가능하게 구체화한 기준이다. 원본에 없던 기능을 구현 완료하거나 별도 승인받았다는 의미가 아니다.

현재 구현 사실은 코드·테스트로 확인하고, 목표 동작은 명세로 확인한다. 템플릿에 기능이 없다는 이유로 기획을 삭제하지 않는다. 구현된 동작과 계약이 충돌하면 `DOC-CODE-MISMATCH`, 결정할 근거가 부족하면 `NEEDS-DECISION`으로 현황에 남긴다.

## 보존 자료

- [핸드오프 원문](chroma_note_handoff_package/chroma_note_project_handoff.md): 최초 기획의 논의 과정과 결정 근거.
- [이미지 포함 핸드오프](chroma_note_handoff_package/chroma_note_project_handoff.html): 해당 기획 위치에 시각 레퍼런스를 배치한 열람본.
- [레퍼런스 출처](chroma_note_handoff_package/REFERENCE_SOURCES.md): 컬러 팬덱, 인덱스, 스와치북, 사진 팔레트의 출처와 용도.
- [원본 패키지 안내](chroma_note_handoff_package/README.md).

원본 4개 파일은 수정·이동·삭제하지 않았다. 원본의 “현재 기준 문서” 표현은 이관 전 맥락으로 보존한다. 이후 변경은 위 정본에 반영하며, 충돌할 때 원본의 의도적 결정을 근거 없이 폐기하지 않는다. HTML의 외부 이미지에는 인터넷 연결이 필요하며, 디자인 작업에서 팬덱·포스트잇·페이지 탭·스와치북의 대표 이미지를 직접 확인했다. 모든 외부 링크의 지속적인 가용성을 보장하지 않는다.

사용자 요청에 따라 `design/`에 편집 원본과 열람본, `docs/design/`에 디자인 기준과 검토 기록을 추가했다. 빈 폴더는 만들지 않는다. 구현 설계가 필요한 작업이 생기면 계획을, 중요한 새 결정이 생기면 ADR을 추가한다.
