# Chroma Note 제품 명세

> 2026-09-09 · Stamp Record 제품 정본. 용어는 [용어집](../CONTEXT.md), 저장·AI 계약은 [기술 명세](02_TECH_SPEC.md), 구현 순서와 미검증 항목은 [현황](03_PROJECT_STATUS.md)을 따른다.

## 1. 제품과 이번 범위

**실제 사진 속 순간을 원본 장면이 남아 있는 Rubber Stamp로 바꾸고, 대표색·AI Field Note·내 메모와 함께 모으는 개인 기록 앱.**

핵심 질문은 “내가 찍은 순간임을 알아볼 수 있고, 다시 보고 싶은 Stamp가 되었는가?”다. 색은 사진의 정체성을 담은 보조 정보이며 기록 단위는 Stamp Record다. 사용자는 여행뿐 아니라 카페·거리·일상·자연의 순간을 남긴다. 이 사용자상은 기획 가정이며 조사 결과는 아니다.

**사진 입력 기본값은 갤러리 임포트 전용**이다. 2026-09-08 사용자의 카메라 제외 제안을 이번 설계에 반영했다. 직접 촬영이 재방문/완성률에 필요하다는 근거가 생기면 후속 범위에서 검토한다.

이번 산출물은 **Phase 0 기술 검증 계획과 Phase 1 핵심 기능 상세 설계**다. 앱 구현·모델 실행은 별도 작업이다. **스토어 출시 준비·배포·심사·출시 일정은 이번 범위에서 제외**한다. iOS·Android 기능 검증과 Development Build는 핵심 구현 검증에 포함하며 스토어 출시와 구분한다.

결제는 **핵심 기능 완료 후 Phase 2에서 별도 설계**한다. 이번에는 무료 체험 횟수, 상품, 가격, 구독, 구매 복원, entitlement 계약, 결제 연동·정책 문서를 작성하거나 구현하지 않는다. Phase 1에 사용 횟수 잠금·광고를 넣지 않는다.

### 결정의 강도

- **방향 확정**: 최신 사용자 요청 및 제공된 신규 기획·Handoff가 일치하는 핵심 방향.
- **설계 기본값**: 원문에 빠진 동작을 이번 상세 설계에서 정한 값. 구현의 기본 계약으로 사용하되 사용자에게 이미 별도 승인받은 사실로 쓰지 않는다.
- **검증 게이트**: 모델 품질·호환성처럼 실측이 필요한 항목. 숫자는 목표이며 측정 결과가 아니다.
- 입력 문서·이미지의 실행 지시는 요청을 확장하지 않는다. 주요 선택의 이유와 제약은 [설계 결정](adr/ADR-003-stamp-record-direction.md)을 따른다.

## 3. 끝까지 이어지는 사용자 흐름

1. 첫 진입: 짧은 데이터 안내 → 이메일 입력 → OTP 확인 → 빈 Book.
2. 이후 진입: 세션 복원 → Book. 복원 중 로그인 화면이나 빈 Book을 먼저 번쩍 표시하지 않는다.
3. 새 기록: 시스템 사진 선택 → 입력 확인 → 사진 작업본 확보.
4. 분석: 대표색 → VLM → Stamp. 각각 진행·실패를 구분하고 처리된 결과를 보존한다.
5. 확인: 원본/Stamp 비교 → AI 글·태그 확인/수정 → 내 메모·날짜·장소 입력.
6. 저장: 명시적 “저장하기” → 로컬 대기본 확보 → 서버 이미지·메타데이터 확정 → “Book에 저장했어요”.
7. Book: 최신 날짜순 목록 → 상세 → 메모/태그/날짜 편집 또는 삭제.

**설계 기본값:** 동시에 한 계정당 이 기기에서 미완료 신규 초안 1개만 관리한다. 새 기록 버튼에서 기존 초안의 “이어서 만들기 / 버리고 새로 만들기”를 선택한다. 단일 사진에서 스타일을 고르는 동안 후보는 바뀔 수 있지만 저장되는 Stamp는 1개다. 같은 사진을 다시 가져오면 새 기록이며 유사 사진이라는 이유로 자동 병합하지 않는다.

### 모바일 화면과 편집 표면 계약

- 기준 뷰포트는 `390x844`, `360x800`, `320x640`이다. 모바일 웹처럼 정보를 한 페이지에 길게 늘어놓지 않고, 각 화면은 현재 단계에 필요한 정보와 주 행동을 한 화면에서 확인하게 구성한다.
- 화면 전체 스크롤은 기본값이 아니다. Book 누적 목록, 200% 글자 확대, 긴 글, 키보드가 열린 편집 시트의 내부 콘텐츠만 스크롤을 허용한다. 화면 전체와 시트의 이중 스크롤은 금지한다. 스크롤을 무조건 0으로 막지 않는다.
- 새 기록은 전체화면 2단계다. `1/2 원본-Stamp 비교`에서 같은 비율의 원본과 Stamp를 확인하고 결과 확인 checkbox를 선택한 뒤 “내용 확인” CTA를 누른다. 확인 전에는 다음 단계와 저장을 허용하지 않는다. 후보 교체·재생성·사진 교체 뒤에는 checkbox를 해제하고 다시 확인하게 한다.
- `2/2 기록 요약`은 Stamp 작은 썸네일, AI 글 2줄과 “글/태그 열기”, 내 메모 요약과 “편집”, 날짜/장소 행, 색상 행, 필수 상태, “저장하기”를 한 화면에 배치한다. 날짜·장소는 중간 높이 시트, 색은 읽기 시트, AI 글·태그는 큰 시트, 메모는 키보드를 고려한 큰 높이 시트로 연다.
- 요약·시트의 “적용”은 로컬 초안만 갱신한다. 서버 저장은 명시적 “저장하기”에서만 확정한다. 영속 저장 실패를 보존 성공처럼 안내하지 않는다.
- 저장된 상세는 큰 Stamp, 날짜·장소, 메모 요약, “글 열기”, “더보기”를 한 화면에 보여 준다. 상세 읽기 시트에서 AI 글과 내 메모 원문을 각각 연다. 편집은 기존 Record 편집 요약과 개별 편집 시트에서 수정하고 “변경 저장”으로 서버 확정한다.
- 삭제·교체·폐기는 중앙 확인 모달을 사용한다. 시트 중첩은 금지한다. 변경 내용이 있을 때 바깥 탭·드래그·뒤로가기로 조용히 버리지 않는다. 기본 닫기는 초안을 보관한 뒤 닫기이며, 취소는 현재 시트 편집만 되돌린다.
- 제품 계약인 AI 원본/임포트/Ink/Supabase를 유지한다. 원본은 비교와 로컬 처리에 사용하고 서버 Record에는 업로드하지 않는다.

## 4. 기능 요구사항

기능 식별자는 **SR-FR-001~012**다. 같은 번호를 다른 의미로 재사용하지 않는다.

### SR-FR-001 — 이메일 인증과 세션

- 가입/로그인을 하나의 “이메일로 계속” 흐름으로 제공한다. 신규 계정 생성 가능성을 발송 전에 안내한다. OTP 발송 성공은 인증 완료가 아니다.
- 앞뒤 공백 제거·이메일 형식 확인 후 발송. 오타 수정, 코드 붙여넣기, 재발송 대기, 잘못된 코드·만료·전송 실패·요청 제한을 구별한다. 입력 횟수 제한은 서버 판정을 따른다.
- 앱 재실행 시 세션을 복원한다. 로그인 이력이 없는 오프라인 기기는 인증 안내까지만 접근한다.
- 이전 인증 계정이 있고 연결이 끊긴 경우 해당 기기의 초안/캐시 열람·로컬 분석을 허용한다. 서버 변경은 재인증 전 확정하지 않는다.
- 토큰 복원 실패·서버가 세션을 거부하면 기록을 지우지 않고 잠근다. 같은 계정 재인증 후 대기 작업을 복구한다. 다른 계정으로 이전하지 않는다.
- 완료: 신규/기존 이메일, 오류/재발송, 재실행, 만료 후 재인증이 같은 계정의 Book으로 연결된다.

### SR-FR-002 — 사진 입력

- 사진 1장, 시스템 갤러리 선택. 동영상·움직이는 이미지·일괄 선택은 제외한다. Live Photo는 접근 가능한 정지 이미지만 사용한다.
- “사진 가져오기”에서 시스템 사진 선택기를 연다. 카메라 화면·직접 촬영·카메라 권한은 Phase 1에서 제외한다. 선택 취소는 오류가 아니다.
- 원본을 변경하지 않고 앱 전용 작업본을 만든다. 방향·색공간을 정규화하고 사진 전체 구도를 유지한다. Stamp 비율을 위해 중앙을 강제 crop하지 않는다.
- 기기의 기본 카메라로 찍은 사진도 갤러리에서 가져온다. 앱은 촬영·사진 앱 쓰기 권한을 요구하지 않는다. 가져온 사진의 작업본이 임시 보관됨을 안내하고 갤러리 원본 삭제 권한은 사용하지 않는다.
- 큰 파일·손상·디코드 불가·iCloud 다운로드 실패·공간 부족을 구별하고 다른 사진 선택을 제공한다.
- 완료: 선택 후 같은 방향과 구도로 비교 화면에 나타나며 취소·입력 교체가 기존 Record를 바꾸지 않는다.

### SR-FR-003 — 대표색 자동 분석

- AI 응답과 무관하게 픽셀에서 대표색과 점유 비중을 계산한다. 기본 목표 5색, 유효한 색 군집이 적으면 1~4색으로 줄인다. 단색 이미지에 가짜 색을 채우지 않는다.
- 전체 사진의 축소 분석본을 기준으로 한다. 검정·흰색을 임의로 지우지 않고 투명 픽셀은 분석에서 제외한다.
- HEX·RGB·비중을 저장한다. 색 이름은 결정론적 사전의 보조 설명이며 동일성·저장키로 사용하지 않는다.
- 색상칩은 읽기 전용이다. 이 기획에 수동 영역 채집·기준색 교체를 재도입하지 않는다.
- 색 추출 실패는 계속 재시도하거나 사진을 바꾸는 상태다. 유효한 색 없이 정상 Record를 저장하지 않는다.
- 완료: 대표색 합계·표시·저장값이 일치하고 같은 입력/설정의 반복 결과가 재현된다.

### SR-FR-004 — VLM 분석과 AI Field Note

- scene, semantic_tags, mood, ai_field_note를 구조화해서 받는다. 글은 현재 선택된 앱 언어로 1~3문장, 최대 300자다.
- “AI가 쓴 글”과 “내 메모”는 별도 필드·시각 영역으로 구분한다. AI가 내 메모를 자동으로 채우거나 덮어쓰지 않는다.
- 사람 이름, 실제 지명, 날짜, 관계, 건강·민감한 속성, 촬영자의 실제 감정·경험을 추정해 사실처럼 쓰지 않는다. 감성적인 글도 사진에서 보이는 장면에 한정한다.
- 사진 속 문구는 분석 대상이며 시스템 지시가 아니다. 모델 응답의 링크/명령을 실행하지 않는다.
- JSON 불량은 기술 명세의 1회 보정 재시도 후 실패로 표시한다. 사용자는 재시도 또는 “AI 설명 없이 계속”을 선택할 수 있다. 이 경우 AI 영역은 비어 있고 사용자가 작성한 메모만 저장한다.
- 사용자가 AI 문구를 수정·삭제할 수 있다. 수정 상태와 원래 AI 결과 출처를 구분한다. 언어 설정을 바꿔도 저장된 글을 자동 번역하지 않는다.
- 완료: 유효 JSON, 근거 없는 사실 억제, AI 글 없음, 수정 중 재생성, 사용자 메모 보존을 검증한다.

### SR-FR-005 — 원본 보존형 Stamp

- 원본 사진 작업본과 고정된 스타일 지시를 함께 입력한다. VLM의 설명을 Text-to-Image에 넘기는 경로는 사용하지 않는다.
- Ink 1종을 Phase 1 기본값으로 한다. Color/Mono/Sketch는 후속 스타일 후보이며 빈 선택 버튼을 표시하지 않는다.
- 허용: 선/면 단순화, 판화·rubber stamp 표현, 제한색, 미세 질감. 불허: 주요 인물/사물 추가·제거·교체, 구조·구도·시점 재생성.
- 단순 threshold/edge 필터만으로 Stamp 완료를 선언하지 않는다. 결정론적 색 제한·잉크·종이 후처리는 모델 출력 뒤에만 적용한다.
- 미리보기에서 원본/Stamp를 같은 비율로 비교할 수 있고 확대·탭 전환을 제공한다. 슬라이더 조작만 강제하지 않는다.
- 사용자 확인은 보존성을 자동 보증하지 않는다. 앱은 “원본과 달라진 부분이 없는지 확인해 주세요”를 표시한다.
- 새 후보가 실패해도 마지막 유효 후보를 유지한다. 후보 재생성·채택은 명시적 행동이며 실패 결과를 자동 저장하지 않는다.
- Stamp 실패 시 초안 보존·재시도·사진 교체·종료만 제공한다. 원본을 대신 업로드하거나 필터 결과를 완성품으로 저장하지 않는다.
- 완료: [AI 검증 계획](05_AI_VALIDATION_PLAN.md)의 보존성·스타일 기준을 통과한 모델 경로에서만 Phase 1 핵심 완료를 주장한다.

### SR-FR-006 — 미리보기·편집·출처

- 필수: 유효 Stamp, 1~5개 대표색, 기록 날짜, 사용자의 결과 확인.
- 선택: AI 글, 장면·의미/분위기 태그, 내 메모, 장소명. AI 글을 지워도 저장할 수 있다.
- 태그/장면은 사용자가 수정·삭제 가능하다. 모델 원문과 사용자 확인본의 구별은 기술 명세의 metadata에 남긴다.
- 내 메모는 최대 2,000자, 장소명 120자, 장면 120자. 태그는 의미 최대 8개·분위기 최대 3개, 각각 24자다. 제한은 입력 시 안내하고 저장 시 다시 검사한다.
- 기본 기록 날짜: 유효한 원래 촬영일 → 없으면 가져온 현지 날짜. 사용자가 수정 가능하며 생성 시각과 구분한다.
- 장소는 Phase 1에서 직접 입력하는 이름만 사용한다. GPS 요청·EXIF GPS 보관·역지오코딩·지명 AI 추정은 제외한다.
- 사진 교체 시 색/AI/Stamp를 무효화하고 메모·수동 날짜·장소는 유지할지 확인한다. 유지하더라도 새 사진의 결과 확인은 다시 받는다.
- 완료: 필수조건 없는 저장 차단, 선택항목 삭제, 길이 경계, 언어 변경, 사진 교체 때 오래된 결과 혼입을 검사한다.

### SR-FR-007 — 초안과 저장 대기

- 작업본 확보와 사용자 편집값은 이 기기에서 복구 가능한 초안으로 보관한다. 화면을 나가면 초안으로 남기고, 명시적 폐기 때만 제거한다. 저장공간 부족으로 초안 확보가 실패하면 “기기에 보관하지 못했어요”를 표시한다.
- 오프라인에서 모델이 이미 준비되어 있으면 로컬 분석·미리보기·메모가 가능하다. “저장하기”는 대기 상태를 만들며 **클라우드 저장 성공으로 표시하지 않는다**.
- Book 위쪽의 “이 기기의 초안 / 저장 대기”와 클라우드 기록을 구별한다. 다른 기기에 초안은 나타나지 않는다.
- 앱 종료/백그라운드 때 진행 중 추론은 중단·재시작 대상으로 처리한다. 세부 연산 지점부터 이어받기를 약속하지 않는다. 완료된 단계와 메모는 복구한다.
- 초안·대기 결과는 자동 만료로 삭제하지 않는다. 사용자가 폐기·로그아웃 폐기 확인·계정 삭제를 선택했거나 서버 저장을 확정한 경우에만 정리한다.
- 완료: 단계별 강제 종료, 네트워크 단절, 재실행·재인증에서 초안 소유와 마지막 편집값이 유지된다.

### SR-FR-008 — Supabase 저장과 재시도

- 명시적 “저장하기” 한 번이 Record 저장 단위다. 입력 중인 태그·메모와 완성 Record 저장을 구분한다.
- 최종 Stamp 이미지와 사용자 확인 메타데이터만 업로드한다. 원본 비교용 이미지를 Stamp와 붙인 합성물도 업로드하지 않는다.
- 로컬 결과 확보 → 서버 비공개 이미지 확보 → 메타데이터 확정 후 성공 안내. 응답을 잃은 경우 같은 ID의 서버 상태를 확인하고 중복 생성하지 않는다.
- 실패한 단계만 재시도하며 저장 재시도가 유료 여부나 AI 재생성과 연결되지 않는다. 서버 중복 요청은 동일 Record 하나로 수렴한다.
- 서버 확정 후 원본 작업본·미채택 후보를 정리한다. 상세에서는 Stamp가 원본을 대신한다. 정리 실패는 재시도 대상으로 남긴다.
- 저장 후 원본 비교·AI/Stamp 재생성은 Phase 1에 없다. 사용자는 사진을 다시 선택해 새 Record를 만든다. 다른 기기에 원본이 복원될 것처럼 안내하지 않는다.
- 완료: 이미지 업로드 후 실패, DB 응답 유실, 중복 탭, 세션 만료, 앱 종료, 잘못된 계정에서 재시도를 검증한다.

### SR-FR-009 — Book·찾기·상세

- 인증 후 시작 화면은 Book이다. 계정의 준비 완료 Record만 기본 목록에 보인다.
- 기본 정렬은 기록 날짜 내림차순 → 생성 시각 내림차순 → ID 순이다. 첫 페이지 30개, 이어 불러오기, 수동 새로고침을 기본값으로 한다.
- 기록 날짜 범위·사용자 확인 의미 태그 1개·즐겨찾기 여부로 필터링한다. 한 Record에 즐겨찾기 boolean을 둔다. 한국어·영어 자유문 검색/의미검색/색 유사도 검색은 Phase 1 제외다.
- 필터 결과 없음, 진짜 빈 Book, 조회 실패, 오프라인 캐시를 다른 상태로 표시한다. 캐시 범위만 보고 전체 기록이 없다고 말하지 않는다.
- 상세 첫 화면에는 큰 Stamp, 기록 날짜·선택 장소, 내 메모 요약, “글 열기”, “더보기”를 둔다. 상세 읽기 시트에서 AI 글과 내 메모 원문을 별도 영역으로 열고, 더보기에서 편집·삭제를 제공한다. 긴 글은 시트 내부 세로 스크롤을 허용한다.
- 다른 기기에서 인증하면 서버 확정 기록을 볼 수 있다. 내려받지 않은 Stamp는 오프라인에서 자리표시와 연결 안내를 표시한다.
- 완료: 0/1/31개 목록, 필터 뒤 복귀, 날짜 이동, 삭제 반영, 이미지 누락, 다른 기기 조회가 계약대로 동작한다.

### SR-FR-010 — 저장된 기록 편집·삭제

- 편집 대상: 날짜·장소·내 메모·태그·AI 표시 글·즐겨찾기. Stamp·추출색·모델 출처는 불변이다.
- 기존 Record 편집은 요약 화면에서 영역별 시트를 열어 날짜·장소·내 메모·태그·AI 표시 글을 수정하고 “변경 저장”을 명시적으로 누른다. 시트의 “적용”은 로컬 편집 초안만 갱신하며 서버 반영 전 수정값을 유지한다. 한 기기에 기존 Record 편집 초안은 동시에 1개만 열며, 다른 Record 편집으로 전환할 때 기존 초안의 저장/폐기를 묻는다.
- 다른 기기가 먼저 수정했으면 자동 덮어쓰지 않는다. 최신 서버 값과 내 수정본을 보여 주고 다시 적용하거나 취소하게 한다. 이미 삭제된 Record를 편집 재시도로 부활시키지 않는다.
- Record 삭제는 확인 후 처리하고 휴지통·되돌리기는 제공하지 않는다. 오프라인은 삭제 예약만 표시한다.
- 삭제 중인 기록은 목록에서 숨기되 “삭제 처리 중”을 따로 알린다. 이미지까지 정리되기 전 “모든 데이터 삭제 완료”라고 표시하지 않는다.
- 완료: 변경 충돌, 중복 삭제, 이미지 삭제 실패, 삭제 중 재시작, 다른 기기 캐시의 새로고침 반영을 검사한다.

### SR-FR-011 — 설정·로그아웃·계정 데이터

- 설정: 언어(시스템/한국어/영어), 모델 준비/저장공간 상태, 데이터 안내, 로그아웃, 계정 삭제.
- 언어는 기존 결정을 유지한다. 시스템 언어가 한국어가 아니면 영어, 사용자의 명시 설정이 우선한다.
- 로그아웃은 이 기기의 계정별 초안·대기 편집·캐시를 제거한다. 미저장 항목이 있으면 서버 저장 후 나가기 또는 폐기 후 나가기를 확인한다. 원격 Record를 로그아웃 때문에 삭제하지 않는다.
- 오프라인에서는 저장 후 로그아웃이 불가능하므로 연결 후 저장·폐기 후 나가기·취소를 제공한다. 폐기 확인을 받은 outbox는 재로그인 후에도 재전송하지 않는다.
- 원격 로그아웃 실패도 로컬 잠금/정보 제거는 수행하되 세션 해제 실패를 알린다. 온라인 재접속 없이 “다른 기기도 모두 로그아웃됨”을 약속하지 않는다.
- 계정 삭제는 온라인 재인증 후 명시 확인한다. 새 저장을 차단하고 Record·Storage·Auth 정리를 재시도 가능하게 처리한다. 실패·진행·완료를 구분한다.
- 단말 오프라인 캐시나 이미 발급된 접근 토큰의 즉각 원격 소거를 약속하지 않는다. 다음 인증 확인/접속 시 잠금·정리한다.
- 완료: 계정 A의 원본·초안·메모·캐시가 계정 B에 노출되지 않고 삭제 중 요청이 데이터를 재생성하지 않는다.

### SR-FR-012 — 모델 준비·처리 상태

- 모델 파일이 없으면 이름·용량·다운로드 필요를 먼저 안내한다. Wi-Fi 권장, 셀룰러 대용량 다운로드는 명시 선택이다.
- 다운로드 중 취소·연결 중단·공간 부족·손상·지원 불가를 구분하고 기기/모델 조합의 지원 여부를 표시한다.
- 모델 준비 전 가져온 사진을 초안으로 보관할 수 있지만 완료 불가능한 변환을 무한 진행 상태로 표시하지 않는다.
- 진행 표시: “사진 준비 / 색 분석 / 사진 읽기 / 스탬프 만들기 / 저장 중”. 실제 측정 가능한 작업 외에는 임의 백분율을 표시하지 않는다.
- 중단 가능한 UI와 처리 시간 초과를 제공한다. VLM/Stamp는 동시에 메모리에 올리지 않는 기본값으로 발열·메모리를 제한한다.
- 완료: 모델 준비됨/없음/손상/미지원, 반복 실행·취소·백그라운드·메모리 부족에서도 초안을 잃지 않는다.

| SR-SCREEN-003 사진 입력 | 시스템 사진 선택·입력 확인 | 권한 거부·취소·손상·과대·공간 부족 |

| SR-SCREEN-007 설정 | 언어·모델·로그아웃·계정 삭제 | 미저장 경고·다운로드·재인증·삭제 진행 |

기본 내비게이션은 Book을 중심으로 “새 기록”을 열고 설정을 헤더에서 접근하는 구조다. 지도/프로필/Ideas를 포함한 5탭을 미리 만들지 않는다. 처리·확인 단계는 전체화면 흐름이며 시스템 뒤로 가기로 초안을 잃지 않는다.

새 기록 단계의 세부 계약은 다음과 같다.

| 단계 | 표면 | 핵심 동작 | 저장 경계 |
|---|---|---|---|
| 1/2 비교 | 전체화면 | 원본-Stamp 비교, 결과 확인 checkbox, “내용 확인” | 확인 전 다음/저장 불가; 후보 교체 후 재확인 |
| 2/2 요약 | 전체화면 | Stamp 썸네일, AI 2줄·글/태그 열기, 메모 요약·편집, 날짜/장소, 색, 필수상태 | 시트 적용은 로컬 초안; “저장하기”만 서버 확정 |
| 기록 읽기 | 상세 + 읽기 시트 | 큰 Stamp·날짜/장소·메모요약·글 열기·더보기 | 읽기 동작은 저장 상태를 바꾸지 않음 |
| 기록 편집 | 기존 Record 편집 요약과 개별 편집 시트 | 메모·날짜·장소·태그·AI 표시 글 편집 | “변경 저장”만 서버 확정 |

시트 규칙은 메모 시트(큰 높이·키보드), 날짜/장소 시트(중간 높이·네이티브 달력), AI 글/태그 시트(큰 높이), 필터 시트(중간 높이), 색 읽기 시트로 고정한다. 원본 확대는 전체화면으로 연다. 모든 시트는 한 번에 하나만 열린다. Android back은 키보드 닫기 → 현재 시트 닫기 순서이며, 그 뒤에도 변경 초안을 보존한다. Reduce Motion에서는 전환을 줄이고 상태를 모션에 의존하지 않는다.

## 7. 시각·접근성 기준

Rubber Stamp와 종이 질감은 결과물에 집중한다. 작업 UI는 읽기 쉬운 무채색, 따뜻한 종이 배경, 명확한 저장 상태를 사용한다. 대표색을 버튼 상태 색과 혼동시키지 않는다. 구체 화면 설계는 [디자인 brief](design/DESIGN_BRIEF.md)가 관리한다.

폰 `390x844`·`360x800`·`320x640`, 태블릿 세로·가로에서 안전영역과 글꼴 확대를 고려한다. 모든 화면·시트·중앙 모달은 실제 런타임 OS inset의 top/bottom/left/right를 적용하며, `390x844` fixture는 status bar 포함 top 62, bottom 34를 기준으로 하고 노치 가로 좌우 inset도 반영한다. iOS 홈 인디케이터, Android 제스처, Android 3버튼 내비게이션을 각각 확인한다. 헤더/풋터는 분리하고 하단 CTA는 홈 영역 위에 배치한다. 키보드가 보일 때는 실제 runtime 높이와 inset을 한 번만 반영하며 이중 차감하지 않는다. 화면 배경/scrim만 안전영역을 침범할 수 있고 인터랙션 콘텐츠는 침범할 수 없다. 조작 영역은 48×48 논리 픽셀을 기본으로 하고 색 외 이름/선택 표시를 함께 제공한다. 한국어·영어·VoiceOver/TalkBack·Reduce Motion·키보드 메모 입력을 핵심 기능 검증에 포함한다.
