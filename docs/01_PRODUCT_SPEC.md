# Chroma Note 제품 명세

> 제품 목표·기능·핵심 UI의 정본. 기술 구현은 [기술 명세](02_TECH_SPEC.md), 진행 상태는 [프로젝트 현황](03_PROJECT_STATUS.md)에서 관리한다.

## 1. 제품 정의와 목표

**일상에서 발견한 색을 사진과 컬러 인덱스로 기록하는 컬러 다이어리.**

주변에서 예쁜 색을 발견했을 때 사진을 찍고, 사진 속 원하는 색을 직접 고른 뒤 인덱스로 붙인다. 시간이 지날수록 자신의 일상이 담긴 Book이 쌓인다. 권장 영문 카피는 `Collect the colors you notice.`이며 최종 배포 카피는 미정이다.

목표는 일상의 색을 다시 보게 하고, 기록 자체가 다시 열어 보고 싶은 결과물이 되는 것이다. 핵심 재방문 동기는 **사용할수록 내 Book이 점점 예뻐진다**이다.

V1은 **무료이며 광고·인앱결제가 없다(Q15)**. 앱을 시작하면 Book을 먼저 보여 주고 촬영 진입을 강조한다(Q16).

## 2. 결정 배경과 제품 경계

| 결정 | 이유와 현재 원칙 |
|---|---|
| Color Hunter에서 컬러 다이어리로 전환 | Daily Color·색 유사도 점수 중심 서비스와 기능만으로 차별화하기 어려웠다. 사진·색·문구의 기록 경험에 집중한다. |
| 하루 1회 제한 제거 | “오늘 미션을 해야 한다” 대신 “저 색 예쁜데?”가 사용 계기다. 원할 때 반복 촬영한다. |
| 정답 판정에서 후보 추천으로 전환 | 조명·그림자·반사·센서·화이트밸런스·노출에 따라 색이 달라진다. 최종 선택은 사용자에게 맡긴다. |
| 사진의 원하는 영역을 직접 선택 | 전체 사진의 자동 팔레트만으로 끝내지 않고, 사용자가 눈여겨본 색을 채집한다. |
| 한 사진에 여러 색 | 사진 하나의 여러 색이 독립 기록이면서 같은 순간에 연결된다. |
| 게임화 축소 | XP·Level·Combo·Leaderboard·Streak 중심 UI는 다이어리 감성을 해친다. ColorDex라는 명칭도 사용자 UI에서 사용하지 않는다. |
| 촬영 후 분석 | 실시간 프레임 분석 없이 핵심 경험을 만들고 구현 난도를 제한한다. |
| Local-first | V1은 서버·계정·로그인 없이 사용하며 사진을 외부로 보내지 않는다. |

원본에서 Rarity·Personal Best는 제거 또는 약한 보조 요소로 남아 있었으나 V1 요구사항에는 포함하지 않는다. 향후 Target 모드 등을 확장할 때도 별도 범위 결정이 필요하다.

## 3. 사용자

아래는 제품 흐름에서 도출한 사용자 가정이며 사용자 조사로 검증된 세그먼트는 아니다.

| 사용자 | 목적 | 주요 행동 |
|---|---|---|
| 일상에서 색을 눈여겨보는 사람 | 발견한 색과 순간을 남기기 | 촬영, 영역 선택, 색 인덱스 붙이기 |
| 사진·다이어리·문구를 즐기는 사람 | 기록을 모아 다시 보기 | 날짜별 Book 열람, 간단한 인덱스 배치 |
| 색을 관찰할 계기가 필요한 사람 | 새로운 관찰 시작 | Ideas 확인, 선택적으로 목표색 찾아보기 |

## 4. 핵심 사용자 흐름

```text
색 발견 → Find에서 촬영 → 사진 영역 터치 → 유사 색 후보 확인
→ 사용자가 색 선택 → Color Index 생성 → 사진에 붙이기 → Book에 저장
                              ↑
                 다른 영역에서 여러 색 추가 가능
```

보조 흐름은 `Book → Diary / Colors → 관련 사진`, `Ideas → 관찰 제안 → Find`다. 목표색을 먼저 고르는 Target은 기본 진입 흐름을 대체하지 않는다.

## 5. 기능 요구사항

단계는 구현 순서다. Phase 1은 핵심 기술 흐름, Phase 2는 다이어리 경험이다. V1에는 갤러리·Ideas(Q5)와 수동 파일 백업·복원(Q10)을 포함한다. Swatches·Monthly Palette·공유·Target·여러 레이아웃은 후속 보완으로 둔다.

아래 **실패/예외·완료 조건은 이관 시 보완한 권장 검증 기준**이다. 원본 흐름을 검증 가능하게 풀어 쓴 것이며 상세 UX가 이미 승인·구현됐다는 뜻은 아니다. 구현 시 범위와 수용 기준을 구체화한다.

### FR-001 — 사진 촬영·갤러리 가져오기 · Phase 1

**목적:** 발견한 색이 있는 순간을 기록한다.

- Find에서 카메라 프리뷰와 커스텀 셔터를 제공하고 촬영 결과로 이동한다.
- 중앙 가이드·안내 문구·견본은 카메라 위 UI로 표현할 수 있다. 움직이는 프리뷰의 색 수치를 실시간 분석하지 않는다.
- 횟수·날짜 제한을 두지 않는다. **갤러리 가져오기를 V1에 포함한다(Q5).** 가져온 사진도 촬영 사진과 같은 영역 선택·색 추천·붙이기 흐름을 사용한다.
- **모바일 감상용으로 최적화한 사본을 보관하고, 해당 사본에서 색을 채집한다(Q17).** 사진 화면·재편집·백업은 같은 보관 사본을 기준으로 한다. 갤러리 원본은 변경하지 않는다. 실제 해상도·압축률은 화질과 실기기 성능을 검증해 정한다.
- 2026-09-07 사용자 최종 지시로 앱 전용 사본 보관을 재확정했다. 사본은 갤러리에 중복 노출하지 않고 앱 내부에서 자동 관리한다. 저장한 뒤 갤러리 원본을 삭제·보정하거나 사진 접근 권한을 철회해도 기존 Book의 보관 사본·채집색은 유지한다.
- 첫 인덱스 전에 나가려 하면 미저장 작업을 버릴지 확인한다. 폐기를 선택하면 미완성 작업을 버리며, 강제 종료 후 초안 복구는 제공하지 않는다(Q8). 갤러리 원본은 앱의 미완성 작업과 구별한다.
- **실패/예외:** 카메라 권한 미허용·거부·카메라 사용 불가·촬영 실패를 구분해 안내한다. 취소·재촬영 시 기존 저장 기록을 훼손하지 않는다.
- **완료 조건:** 촬영한 사진이 색 선택 화면에 나타나고, 연속으로 새 기록을 시작할 수 있으며, 실패 후 재시도가 가능하다.

### FR-002 — 영역별 색 추천과 다중 선택 · Phase 1

**목적:** 사진에서 사용자가 눈여겨본 색을 고른다.

- 사진을 터치하면 샘플 위치를 표시하고 해당 위치 주변의 대표색을 구한다.
- 가까운 기준 색 **3~5개**를 이름·스와치와 함께 제시한다. 하나를 정답으로 강제하지 않는다.
- 사용자가 최종 후보를 선택하며, 같은 사진의 다른 영역에서 색을 추가할 수 있다.
- **색의 의미(Q3 확정):** 인덱스는 사용자가 고른 기준색으로 표시한다. 사진에서 실제 채집한 색도 별도로 보존하며 선택한 기준색으로 덮어쓰지 않는다. 기준색과 채집색이 다르다는 이유로 저장을 막지 않는다.
- 수치는 핵심 UI에서 강조하지 않는다. `very close`, `close` 등의 부드러운 표현은 후보이며, 상세 유사도 표시와 문구의 최종 기준은 미정이다.
- **실패/예외:** 사진 밖 터치는 무시하고, 분석 실패 시 위치 재선택·재시도를 제공한다. 분석 중 연속 입력으로 다른 위치의 후보가 잘못 붙지 않아야 한다.
- **완료 조건:** 영역 변경에 따라 후보가 갱신되고, 사용자가 선택한 두 개 이상의 색이 같은 사진에 연결된다. 분석 실패를 색 선택 성공으로 처리하지 않는다.

### FR-003 — Color Index 배치와 저장 · Phase 1 저장 / Phase 2 표현

**목적:** 고른 색을 사진의 일부이자 분류·장식으로 남긴다.

- 선택한 색은 사진 옆·아래·페이지 가장자리에 붙는 Color Index로 표현한다.
- **붙일 때마다 저장한다(Q4 확정).** 첫 인덱스를 붙이면 사진과 해당 색을 Book에 보존한다. 다른 색을 추가하지 않고 화면을 나가도 이미 붙인 기록은 남는다. 사진 단위의 별도 완료 버튼으로 저장을 미루지 않는다.
- 추가 인덱스는 같은 사진에 연결해 저장한다. 색을 추가할 때마다 사진 기록을 새로 만들지 않는다.
- 한 사진에는 **서로 다른 기준색 최대 5개**를 붙인다(Q11). 이미 붙인 기준색을 다시 고르면 기존 인덱스로 안내하고 새 색 기록을 만들거나 기존 채집색을 덮어쓰지 않는다.
- 인덱스 위치 조정·색 변경은 각 조작을 완료했을 때 저장한다(Q13). 드래그 중간 좌표마다 완료 처리하지 않는다. 변경 대상 기준색이 같은 사진에 이미 있으면 중복을 만들지 않는다.
- **마지막 인덱스를 떼어도 사진 기록을 남긴다(Q9).** 색이 없는 사진을 Book에서 열어 다시 색을 붙일 수 있다. 사진 기록 삭제는 별도 동작이다.
- 사진 기록 전체 삭제는 확인 후 처리하며 V1에는 휴지통을 두지 않는다(Q13). 갤러리의 원본이나 이미 내보낸 백업 파일을 함께 삭제하지 않는다.
- 사진 기록 전체를 삭제하면 해당 기록의 앱 전용 사본과 관련 캐시도 자동 정리한다. 사용자가 파일을 따로 찾아 삭제할 필요가 없게 한다. 마지막 인덱스만 제거한 경우에는 보관 사본을 유지한다.
- 자유로운 모든 오브젝트의 resize·rotate·layer 편집은 제외한다. 작은 회전과 제한된 페이지 레이아웃으로 충분하다.
- **실패/예외:** 저장 실패 시 성공 애니메이션·완료 상태로 끝내지 않는다. 선택 내용을 유지해 재시도할 수 있어야 한다. 저장 중 반복 입력으로 기록이 중복되지 않아야 한다.
- **완료 조건:** 사진·선택색·배치가 서로 맞게 저장되고 앱 재실행 후 복원된다. 인덱스를 변경·제거해도 같은 사진의 다른 색 기록은 유지된다.

### FR-004 — Book / Diary · Phase 2

**목적:** 날짜별로 쌓이는 자신의 컬러 다이어리를 살펴본다.

- 날짜별 여러 사진과 각 사진의 Color Index를 함께 보여 준다.
- 마지막 색을 제거한 사진도 Diary에 유지한다. 색이 없는 기록에는 색을 다시 붙일 수 있는 진입점을 제공한다(Q9).
- 촬영 사진은 촬영일, 갤러리 사진은 유효한 원래 촬영일을 우선 사용한다. 촬영일을 알 수 없으면 가져온 날짜를 사용하며 사용자가 Diary 날짜를 수정할 수 있다(Q12).
- 선택적 메모를 제공하며 입력 조작 완료 시 저장한다(Q13). 날짜 수정도 조작 완료 시 반영한다. 마스킹 테이프는 선택적 장식이다.
- 앱을 새로 시작하면 Book을 먼저 표시한다(Q16). 기록이 없으면 첫 촬영·갤러리 가져오기를 안내하고, 기록이 있으면 Diary와 촬영 진입을 보여 준다.
- **실패/예외:** 기록이 없으면 첫 촬영으로 안내하고, 읽기 실패는 빈 Book과 구분한다. 사진 파일이 없거나 깨진 경우 확인 가능한 기록 정보와 오류 상태를 표시한다.
- **완료 조건:** 저장한 사진이 해당 날짜에 나타나고 연결된 색을 확인할 수 있다. 다른 날짜·여러 사진·재실행 상태에서도 연결이 유지된다.

### FR-005 — Colors · Phase 2

**목적:** 모은 색을 기준으로 기록을 다시 찾는다.

- 수집된 색을 목록으로 보여 준다. hue 기준의 자연스러운 정렬은 권장안이며 최종 정렬 방식은 미정이다.
- **선택한 기준색별로 묶는다(Q7).** 서로 다른 사진이 같은 Coral을 선택했다면 Colors에는 Coral 하나가 나타나고, 이를 열면 연결된 사진들을 본다. 이름 번역이나 실제 채집색 차이로 그룹을 나누지 않는다.
- 현재 연결된 색 기록이 없는 기준색은 Colors의 수집 목록에 나타나지 않는다. 무채색 정렬 규칙은 후속 설계에서 정한다.
- **실패/예외:** 수집색 없음, 관련 사진 없음, 조회 실패를 구분한다.
- **완료 조건:** 여러 사진에 연결된 색을 찾아 관련 사진을 볼 수 있고, 인덱스 변경·제거 결과가 목록에 반영된다.

### FR-006 — Ideas · V1 포함(Q5)

**목적:** 일상의 색을 관찰할 작은 계기를 준다.

- “하늘이 아닌 파랑을 찾아보세요”, “서로 다른 초록 세 가지를 찾아보세요”, “이름을 모르는 색을 찾아보세요”와 같은 제안을 제공한다.
- V1은 앱에 포함된 관찰 문장을 제공한다. 사용자가 Ideas를 작성·수정하는 편집 기능은 포함하지 않는다.
- 완료·점수·보상·사용 횟수를 강제하지 않는다. Target 색과의 연결은 FR-009를 추가하는 후속 범위다.
- **실패/예외:** 제안을 완료하지 않아도 촬영·Book을 사용할 수 있다. 제안 데이터가 없을 때도 핵심 기능은 유지한다.
- **완료 조건:** 관찰 문장을 확인하고 자유롭게 촬영으로 이동할 수 있다. 완료 판정이 앱 사용을 막지 않는다.

### FR-007 — Swatches · V1 이후

- 모은 색 또는 탐색 가능한 색을 견본 카드·목록으로 꺼내 본다.
- 팬덱의 펼치기·고르기 감각을 참고하되 고급 팬 애니메이션은 이후로 미룰 수 있다.
- **완료 조건:** 색 이름과 견본을 확인할 수 있고 빈 상태가 처리된다. 고급 애니메이션 유무를 완료 조건으로 삼지 않는다.

### FR-008 — Monthly Palette / 공유 · 후속 우선 기능

- 월간 색 기록과 선택적 사진을 하나의 결과물로 구성해 회고·공유에 활용한다.
- V1 핵심 릴리스의 필수 조건은 아니다. 상세 집계 기준, 레이아웃, 내보내기 형식은 후속 설계에서 정한다.
- **완료 조건:** 구현 범위를 정한 뒤 기간에 맞는 기록만 포함되는지, 기록 없음·공유 취소·내보내기 실패를 확인한다.

### FR-009 — Target Color · 후속 보조 기능

- 견본을 미리 선택하고 주변에서 비슷한 색을 찾아볼 수 있다.
- 메인 내비게이션으로 승격하지 않는다. 촬영 후 후보를 사용자가 선택하는 원칙을 유지한다.
- **완료 조건:** 목표색을 고른 뒤 Find로 이어지고 자유 촬영으로 돌아올 수 있다. 목표 달성 실패가 기록을 막지 않는다.

### FR-010 — 수동 파일 백업·복원 · V1 포함(Q10)

**목적:** 계정·서버 없이 기기 교체나 앱 재설치에 대비해 기록을 사용자가 보관한다.

- 사용자가 사진·실제 채집색·선택한 기준색·인덱스 배치·수정한 기록 날짜·메모가 포함된 백업 파일을 만들고, 선택한 백업 파일에서 기록을 복원할 수 있다.
- 백업의 사진은 앱에 보관한 최적화 사본이다(Q17). 갤러리 원본 파일이나 원본 해상도의 보관을 보장하는 기능으로 안내하지 않는다.
- 복원한 사진도 앱 전용 보관 사본으로 관리하며 갤러리 재연결을 요구하지 않는다. 사본 누락·손상은 실패로 안내하고 불완전한 백업을 완료로 처리하지 않는다. 갤러리 참조안에서 논의했던 부분 백업은 V1 범위에서 제외한다.
- 앱이 자동으로 서버에 전송하거나 기기 간 동기화하지 않는다. 백업 파일 보관과 가져오기는 사용자가 직접 수행한다.
- 백업 생성과 결과 파일 저장·전달의 취소/실패를 완료로 표시하지 않는다. 복원 전 파일 유효성을 확인하고, 손상·미지원 형식·공간 부족에서 기존 기록을 보존한다.
- **새 사진 기록만 병합하고 같은 기록 ID는 현재 기기의 기록을 유지한다(Q14).** 같은 기록의 색·배치·메모를 백업 값으로 덮어쓰거나 추가 혼합하지 않는다. 복원 결과에는 추가한 기록과 이미 있어 건너뛴 기록을 구분해 알린다.
- 삭제한 사진도 오래된 백업에 남아 있고 현재 Book에 없다면 다시 가져올 수 있다. 복원은 삭제·편집 상태를 양방향으로 맞추는 동기화가 아니다.
- 백업은 사용자 기록을 대상으로 한다. 앱 언어 설정은 복원 대상에서 제외해 현재 기기의 설정을 유지하고, 앱에 포함된 Ideas 문장은 현재 앱에서 제공한다. 지원 버전·파일 크기 한계는 기술 설계에서 정한다.
- **완료 조건:** 사진·색·배치가 포함된 백업을 다른 앱 설치 환경에서 복원할 수 있다. 색이 없는 사진(Q9)도 포함하며, 실패한 복원이 기존 Book을 훼손하지 않는다.
- 원본의 후속 범위를 V1으로 변경한 근거는 [백업 결정](adr/ADR-001-local-backup.md)에 기록했다.

## 6. 화면 / UI 상태

하단 구조는 **Find · Book · Ideas**, 앱 시작 화면은 **Book(Q16)**이다. V1 Book은 Diary·Colors 보기를 제공하고, Swatches는 후속 확장이다. 별도 최상위 탭을 늘리지 않는다. 실제 라우트 이름과 화면 분할은 구현 설계에서 정한다.

| ID / 화면 | 진입·구성 | 주요 행동 / 다음 화면 | 처리할 상태 |
|---|---|---|---|
| SCREEN-001 Find | Find 탭, 카메라·셔터·가이드·갤러리 진입 | 촬영/가져오기 → Photo Color Pick | 권한 확인, 거부, 초기화, 준비, 촬영/가져오기 중, 취소, 실패 |
| SCREEN-002 Photo Color Pick | 촬영/가져오기 성공 또는 기존 사진, 사진·마커·후보 이름/스와치 | 위치 선택·여러 색 추가 → Index Placement, 재촬영 → Find | 미선택, 분석 중, 후보 표시, 선택됨, 중복 기준색, 5개 상한, 분석 실패 |
| SCREEN-003 Index Placement | 선택색 존재, 사진·Color Index | 위치 조정·변경·떼어내기·붙이기 → Book | 편집, 저장 중, 저장 완료, 저장 실패 |
| SCREEN-004 Book / Diary | 앱 시작·Book 탭, 날짜·사진·인덱스·선택적 메모 | 기록 열람·날짜/메모 수정·사진 삭제, Colors 전환, 촬영/가져오기 → Find | 조회 중, 빈 기록, 0색 사진, 목록, 읽기 실패, 사진 누락, 삭제 확인 |
| SCREEN-005 Colors | Book의 색상 보기, 수집색 목록 | 색 선택 → 관련 사진 | 조회 중, 수집색 없음, 목록, 관련 사진 없음, 오류 |
| SCREEN-006 Ideas | Ideas 탭, 관찰 문장·선택적 견본 | 관찰 시작 → Find | 제안 표시, 제안 없음, 선택 상태 |
| SCREEN-007 Swatches | Book의 견본 보기, 카드·이름 | 견본 탐색·선택 | 빈 견본, 카드 표시, 선택 상태 |
| SCREEN-008 설정 | 진입 위치는 후속 설계, 언어·백업/복원 | 언어 변경, 백업 생성·파일 선택·복원 | 언어 선택, 처리 중, 완료, 취소, 유효하지 않은 백업, 저장공간 부족, 실패 |

Photo Color Pick과 Index Placement는 경험의 단계 구분이며 반드시 별도 라우트일 필요는 없다. 붙인 인덱스는 이미 저장된 기록이다. 화면 이탈을 이유로 이를 취소하지 않는다. 첫 붙이기 전 이탈은 폐기 확인을 거치며 초안 복구는 제공하지 않는다(Q8). 저장된 사진에서 추가 중인 미부착 선택의 이탈 처리는 같은 원칙을 적용하되 이미 저장한 기록을 유지한다.

### 시각·인터랙션 원칙

- **컬러 팬덱 + 인덱스 포스트잇 + 다이어리/스크랩북**의 물리적 경험을 결합한다. 특정 브랜드·앱 UI를 복제하지 않는다.
- 배경은 따뜻한 off-white, UI는 무채색 중심으로 둔다. 종이 질감은 필요할 때 매우 약하게만 사용하고 과한 그라데이션·무지개 장식을 피한다.
- 본문은 깔끔하고 읽기 쉽게 만든다. serif·손글씨는 날짜나 작은 메모의 강조에 제한하고 전체 UI에 사용하지 않는다.
- 여백, 약간 어긋난 사진, **1~3도** 정도의 회전, 사진 밖 인덱스, 선택적 테이프로 문구 감각을 표현한다. 읽기 순서와 터치 사용성을 해치는 무작위 배치는 피한다.
- 색 선택의 작은 햅틱, 인덱스 붙이기, Book 페이지 이동, 견본 꺼내기에 절제된 모션을 적용한다. 게임식 보상 효과를 넣지 않는다.
- 편집은 인덱스 위치와 작은 회전, **2~3개 페이지 레이아웃** 정도가 권장 상한이다. 여러 레이아웃은 Phase 3에서 보완할 수 있다.

### 사용자 용어

| 개념 | 사용자 표현 |
|---|---|
| 앱 / 촬영·발견 / 전체 기록 | Chroma Note / Find / Book |
| 날짜별 기록 / 색상별 보기 / 색 견본 | Diary / Colors / Swatch |
| 사진에 붙이는 색 라벨 / 관찰 제안 | Color Index / Ideas |
| 월간 색 모음 | Monthly Palette |
| 저장 / 삭제 | 붙이기 / 떼어내기 |
| 카드 / 필터 / 공유 / 목표 | 종이 조각 / 색 인덱스 / 페이지·Palette / 견본 골라보기 |

Color Index는 앱 이름이 아닌 시각 오브젝트 이름이다. **한국어·영어 UI를 모두 제공한다(Q2). 시스템 언어를 기본으로 따르고 앱에서 변경할 수 있으며, 색 이름도 선택 언어로 번역한다. 지원 외 시스템 언어에서는 영어를 사용한다(Q6).** 영문 용어는 기획상 기준 명칭이며 탭의 영문 브랜드 표현 유지 여부와 최종 번역 문구는 후속 설계에서 정한다.

채집색·기준색·ColorSample·Color Index의 정의는 [용어집](../CONTEXT.md)을 따른다. 위 표는 화면 표현을 위한 명칭이다.

## 7. 공통 규칙

- **BR-001:** 하루 1회 제한, 촬영 미션 강제, 스트릭 중심 사용 제한을 도입하지 않는다.
- **BR-002:** 앱은 가까운 색을 추천하고 사용자가 선택한다. 성공/실패 점수로 기록 자격을 판정하지 않는다.
- **BR-003:** 한 사진에 여러 색을 연결한다. 인덱스에는 선택한 기준색을 표시하고 실제 채집색도 별도로 보존한다(Q3).
- **BR-004:** V1 색 분석은 촬영 후 수행한다. 실시간 pixel sampling·frame processor·object detection을 포함하지 않는다.
- **BR-005:** V1은 로컬에서 동작한다. 서버·로그인·SNS·친구·랭킹·클라우드 동기화·AI API를 추가하지 않는다. 위치정보는 필수가 아니다.
- **BR-006:** 수집률·XP·Level·Rarity·Combo보다 사진과 색의 기록을 중심에 둔다. 대시보드형 UI를 만들지 않는다.
- **BR-007:** Color Index는 분류와 장식을 겸한다. 붙일 때마다 사진·해당 색을 저장하며 이미 붙인 기록은 화면 이탈 후에도 남는다(Q4).
- **BR-008:** 색만으로 상태를 전달하지 않는다. 이름·텍스트 보조, 읽을 수 있는 대비, 사용 가능한 터치 영역과 접근성 이름을 제공한다.
- **BR-009:** 분석은 체감상 즉시 또는 짧게 끝나야 한다. 수치 성능 예산은 아직 없으며 실제 기기에서 확인한다.
- **BR-010:** 상용 색상 시스템을 무단 복제하지 않는다. 자체 기준색 목록과 레퍼런스 출처를 관리한다.

## 8. 범위와 릴리스 기준

| 범위 | 포함 |
|---|---|
| 첫 마일스톤 — Core | FR-001·002, FR-003의 로컬 저장: 촬영 → 영역 대표색 → 3~5개 후보 → 다중 선택 → 재실행 후 보존 |
| V1 기본 경험 | Core + FR-003의 인덱스 편집, FR-004·005, 기본 종이/인덱스 디자인·작은 모션·햅틱 |
| V1 확정 추가 | FR-001 갤러리 가져오기·FR-006 Ideas(Q5), 한국어·영어 전환·색 이름 번역(Q6), FR-010 수동 파일 백업·복원(Q10) |
| 후속 보완 | FR-007·008·009, 여러 페이지 레이아웃 |
| 이후 검토 | 팬덱 고급 모션, Widget, 클라우드 동기화, AI object label, 실시간 분석 — 별도 범위 결정 후 검토 |

**첫 버전의 목표는 스토어에 정식 출시할 V1이다.** 2026-09-07 기획 보완 인터뷰 Q1에서 사용자가 확정했다. Core는 중간 구현 마일스톤이며 첫 버전의 최종 완료 기준은 아니다.

**출시 대상은 iOS·Android이며 한국어·영어를 지원한다**(2026-09-07 인터뷰 Q2 확정). 출시 일정·상세 배포 절차는 아직 미정이다. 갤러리·Ideas·수동 백업/복원은 Q5·Q10에서 명시적으로 추가했으며, Monthly Palette·공유 등 나머지 후속 기능을 자동으로 포함하지 않는다. 아래 릴리스 검증안을 바탕으로 세부 정책·데이터 보존 안내·배포 준비 기준을 후속 인터뷰에서 구체화한다.

- [ ] 촬영 → 다중 색 선택 → 붙이기 → Book 열람이 연결된다.
- [ ] 저장 후 앱을 다시 실행해도 사진·선택색·인덱스가 보존된다.
- [ ] 채집색과 다른 기준색을 선택해도 인덱스에는 기준색이 보이고 채집색 값은 보존된다.
- [ ] 첫 인덱스 저장 후 화면을 나가도 사진이 남으며, 다음 인덱스 저장 실패가 앞서 저장한 기록을 지우지 않는다.
- [ ] 날짜별 Diary와 Colors에서 관련 기록을 찾을 수 있다.
- [ ] 갤러리 사진에서도 다중 색 선택·저장을 할 수 있고 Ideas는 관찰을 강제하지 않는다.
- [ ] 사진 표시·색 채집·재편집·백업이 같은 최적화 사본을 기준으로 하며, 갤러리 원본은 변경하지 않는다.
- [ ] 저장 후 갤러리 원본 삭제·보정·권한 철회에도 Book이 유지되고, 사진 기록 전체 삭제 시 앱 사본·캐시가 자동 정리된다.
- [ ] 시스템 언어·앱 언어 변경·영어 기본값이 적용되고, 번역 후에도 기준색 그룹과 기록 연결이 유지된다.
- [ ] 첫 저장 전 이탈 확인·폐기, 마지막 색 제거 후 사진 유지가 명세대로 동작한다.
- [ ] 사진당 5색·중복 금지를 지키며 날짜·메모·배치 편집이 조작 완료 시 저장된다.
- [ ] 갤러리 촬영일의 존재/누락과 날짜 수정, Book 시작·빈 상태, 확인 후 사진 삭제를 검증한다.
- [ ] 수동 백업·복원으로 사진·색·배치가 복원되며 취소·실패·손상된 파일이 기존 기록을 훼손하지 않는다.
- [ ] 같은 백업을 반복 복원해도 중복 기록이 늘지 않고 현재 기기에 있는 같은 ID의 수정 내용을 유지한다.
- [ ] 권한 거부·촬영/분석/저장/읽기 실패·빈 상태를 구분하며 기록을 잃지 않는다.
- [ ] 실제 기기에서 영역 선택의 정확성, 분석 반응성, 작은 화면의 가독성·터치·접근성을 확인한다.
- [ ] iOS·Android 각각에서 핵심 흐름을 검증하고 한국어·영어의 문구 누락·잘림과 접근성 이름을 확인한다.
- [ ] V1 제외 기능·네트워크 의존성을 추가하지 않았고, 데이터 손실 등 치명적인 알려진 문제가 없다.
